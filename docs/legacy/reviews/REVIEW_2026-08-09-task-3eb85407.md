## 5. 前端 Bug：`Unknown event type "operation_progress"`（已修复）

- **修复**（三个解析文件 + 测试）：
  - `apiResponseParsers.ts`：`assertEventType` 白名单 + `RUNTIME_EVENT_TYPES` 加入 4 类 operation 事件
  - `eventParsers.ts`：payload 路由集合补 4 类
  - `eventParsersRuntime.ts`：实现 4 个 operation payload 解析分支（含默认 `succeeded` 状态、ErrorDetail 复用）
  - 新增 11 项回归测试（含复现原报错的 `parseEventPage` 完整 envelope 回放），36+115 前端测试通过

## 7. 遗留与建议

- **P0（已落实 2026-08-09）**：GEO probe→gene 映射接线——GPL 注释下载 → `mapping_paths`/`mapping_assets` 注入 runner，使探针平台数据集能产出基因级或 probe-primary（`gene_expression.probe_release.v1`）产物。实现：
  - GEO 技能新增 `download_geo_platform_annotation(gpl)` 操作（复用 `geo_annotation.discover_annotation_file` 发现 + `acquire_source` 内容寻址下载，带 provenance）；
  - `execute_dataset_build` 新增可选 `mapping_files` 参数（binding_id → 注释文件相对路径），经共享 `_resolve_local_assets` 包装为 SourceAsset 并注入 `ExpressionBuildRunner`（mapping_assets/mapping_paths）与 `DatasetBuildExecutor`；
  - executor input digest 纳入 mapping_assets 哈希（换注释重跑不复用陈旧 canonicalize 检查点）；
  - agent.py INSTRUCTIONS 指导探针平台基因级构建先下注释再传 mapping_files，无注释时退回 GDC/Xena 或 probe 级并如实告知。
  - 新增测试：技能操作 3 项、工具 mapping_files 3 项、digest 失效 1 项、INSTRUCTIONS 断言 1 项（后端全量 2316+ passed）。

  **设计评估（必要性/合理性）**：
  - 必要性：正确性本就 fail-closed（无注释 → 诚实 NO_DATA + `probe_mapping_unavailable_required_gene_level`）；本接线是**能力完备性**修复——把"GEO probe 数据集对基因级任务永远不可用"变为"有可用注释的平台（Affymetrix/Illumina 等）可真正产出基因级结果"，直接回应 08-05 REVIEW §3.1 P0 的实证（Agilent 注释列全空导致产物是"盲盒"）。对单基因差异任务 GEO 仍是回退通道（GDC/Xena 优先），故边际价值集中在"唯一来源是 GEO 探针平台"的场景——仍属赛题"数据查找完备性"要求。
  - 合理性（为何选"Agent 下载 → mapping_files 显式注入"而非 runner 自下载）：runner/内核保持确定性（网络只在 Agent 侧，符合双层面架构）；注释以 SourceAsset 进入溯源链（sha256 + DownloadAttempt，F2 双向不变量由 `build_probe_mapping` 强制）；与既有 `source_files` 模式一致、无约定魔法。否决方案：runner 内自下载（破坏确定性、内核引入网络）；按约定自动发现（隐式魔法、弱报错）。
  - 边界：`mapping_files` 是可选的——probe 级构建（`probe_release.v1`）与纯 gene 级 GDC/Xena 构建不受影响；错传平台注释（与 batch 平台不符）→ 覆盖率 0 → 既有诚实失败路径兜底，无数据丢失。
