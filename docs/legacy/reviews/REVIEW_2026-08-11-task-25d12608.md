## 3. 问题①：`ReadError` 失败根因（用户问的"调用失败原因"）

### 3.1 结论：模型 API 网络层瞬时断连，不是工具错误

- 异常显示为 `ReadError` 且无 message：`httpx.ReadError`（连接被对端/网络中途断开）的 `str()` 为空，manager 捕获处 `str(error) or type(error).__name__`（manager.py:1694/1837）回退为类名。
- 传播路径：`_consume_events` 迭代 SDK 流 → `runner.py:1119` generic `except Exception` 不匹配 `_is_qwen_function_args_error` → re-raise → `__call__` → manager `_dispatch_run` → run FAILED（error_code=`internal_error`）。
- **"LLM 调用工具出错"的感知与事实不符**：工具参数错误（`invalid_arguments`）走的是在带返回，Agent 当场恢复（本轮它改用正确参数继续搜索并 describe 了 4 个数据集）；真正杀死 run 的是**模型调用层的网络异常**，与工具无关。

### 3.2 为什么没有自动重试

`agent_loop/runner.py` 已有 4 条恢复路径，但**没有网络错误这条**：

| 已有恢复路径 | 触发条件 | 处理 |
| --- | --- | --- |
| `MaxTurnsExceeded` | SDK 超轮次 | pause-resume（用户决定） |
| `NoProgressDetected` | 工具重复无进展 | pause-resume（用户决定） |
| Qwen `function.arguments` 400（`QWEN_FUNCTION_ARGS_RETRY_LIMIT=2`） | DashScope 400 参数 JSON 非法 | 自动丢弃非法调用 + 修正指令重试 |
| 空输出（`EMPTY_OUTPUT_RETRY_LIMIT=2`） | 仅 reasoning 无输出 | 自动提示"继续"重试 |
| **（缺口）瞬时网络错误** | `httpx.ReadError/ConnectError/超时`、DNS | **无——直接 re-raise，run FAILED** |

此外 `app/agent_loop/model.py:156 build_openai_client` 未显式配置 httpx 超时与 `max_retries`（走 SDK 默认，且 SDK 默认重试不覆盖流式中断）。run1 的 DNS 失败发生在客户端惰性构建（`_get_delegate` 首次调用），同样无重试。

## 5. 问题③：自动重试设计

### 5.1 识别可行性（回答"似乎不太好识别？"）

**可识别，且边界清晰**。瞬时（可自愈）错误收敛在固定异常集合：

| 类别 | 异常 | 判定 |
| --- | --- | --- |
| 连接层 | `httpx.ConnectError`、`httpx.RemoteProtocolError` | 瞬时 → 重试 |
| **读取层（本轮 ReadError 属于此类）** | `httpx.ReadError`、`httpx.ReadTimeout`、`httpx.PoolTimeout` | 瞬时 → 重试 |
| 超时 | `httpx.ConnectTimeout`、`asyncio.TimeoutError` | 瞬时 → 重试 |
| DNS | `socket.gaierror`、`UnsafeUrlError("URL hostname could not be resolved…")`（network_safety.py:54） | 瞬时 → 重试（注意与普通 UnsafeUrlError 区分：仅 DNS 解析失败的文案可重试） |
| SDK 包装 | `openai.APIConnectionError`、`openai.APITimeoutError` | 瞬时 → 重试 |

**不重试**（持久错误，重试必败）：`AuthenticationError`（401/403）、`BadRequestError`（400，已有 Qwen 专用重试）、`NotFoundError`（404）、模型不存在、参数非法、限流后的配额错误等。

### 5.3 重试安全性论证（备查）

- **副作用不重复**：网络错误发生在模型调用层；此前完成的工具调用已持久化在 durable session，`agent_input=[]` 续跑不会重放历史工具调用（同 max_turns 续跑语义，runner.py:1114-1117）。
- **mid-stream 失败安全**：模型流式中断时，assistant 内容尚未作为 message item 提交 session（文本缓冲到 finish_reason 才落库），重试不会产生残缺 assistant 消息。
- **与既有恢复路径不冲突**：按 `except` 顺序置于 Qwen 400 分支之后、`raise` 之前即可。
