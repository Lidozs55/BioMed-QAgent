## 1. 项目概述

**BioMed-QAgent** 是一个面向生物医学开放数据的智能检索与整合系统。用户只需**用自然语言描述研究主题**（例如“Ⅰa 型超新星光变曲线”），系统即可自动完成**查找来源 → 获取原始数据 → 解析、清洗与字段对齐 → 整合 → 产出带完整来源与审计信息的标准化表格**的全流程，把“**从科学问题到可直接分析的数据**”这一研究场景自动化。

系统有一条贯穿始终的设计底线：**让 AI 只做“数据统合引擎的操作者”，而不做“数据的编写者”**——不靠模型“猜”出一张表格，也不在缺少数据证据时编造科研或临床结论。真正修改与组织数据的，是一系列**确定性、可信、可审计**的机制；每一份正式产物都必须经过**确定性的验证门禁**才会发布，每一条数据都能回答“**它来自哪里、被怎样处理过、用的是哪个版本**”。

整套系统按“**智能层 + 受控执行层 + 产品信任层**”分层构建：智能层负责理解与产出“做什么”，受控执行层负责“安全地做”，数据内核负责“判定能不能信、能不能发布”。这一分层是全部设计的基石——**“可信”来自完整的准入、隔离与内核门禁，而不是某段代码的作者身份，也不是模型的自信程度。**

## 2. 需求分析与痛点

本系统对应赛题“**从科学问题到可用数据**”的真实研究场景：系统的首要任务是**构建标准化、可直接用于后续分析的可用数据集**（以合并后的多源表格为核心产物），而非完成一项完整的研究。围绕这一目标，我们在生物医学数据检索与整合的实际场景中识别出以下核心痛点，并逐一对应到系统的设计方案。

| # | 场景痛点 | 对应的设计方案 | 详见 |
| --- | --- | --- | --- |
| P1 | **数据源分散、格式与标准不一**：科学数据散落 PubMed、GEO、GDC 等数十个库与文献，无统一入口 | 多来源适配器 + 内容寻址“源资产” + 模式（Schema）驱动解析，统一汇入确定性内核 | §3.1 / §4.1 |
| P2 | **模型易“幻觉”字段与结论**：大模型会“猜”字段含义、临时合并，缺证据时甚至编造结果，难以复现 | 确定性数据内核（七步流水线）；字段对齐靠规则 + 可信元数据，**字符串相似度只产生“候选提议”**；无证据不产出正式产物 | §4.2 / §5.1 / §5.3 |
| P3 | **多源数据不可直接合并**：行粒度、主键、计量单位、表达体系各不相同，直接合并产生“假整合” | **兼容性门禁**——仅当数据族、行粒度、主键、测量兼容才允许合并；单位与表达规范化 | §4.2 |
| P4 | **来源难追溯、难验证**：学术场景下每条数据须能回答“来自哪、如何处理、何版本”，否则无法复现引用 | 全链路溯源——内容寻址 + 摘要，清单文件为产物唯一权威，可回溯到原始来源与处理版本 | §4.4 / §5.6 |
| P5 | **大数据量内存膨胀**：表达矩阵等大表在朴素内存去重/分组时易溢出 | **磁盘化去重/分组**（内嵌数据库临时表 + 流式迭代 + 资源上限） | §4.2 / §5.7 |
| P6 | **数据质量问题缺乏系统处理**：缺失、重复、单位不一致零散难处理 | 自动异常识别 + **失败行进入审计而非静默丢弃** + 人在回路“寻求人工建议后修正” | §4.3 / §6 |
| P7 | **图表/图像数据难提取、难验证**：大量数据以论文图表/图像形式存在 | 浏览器截图 + 视觉大模型 / 文档解析 / 说明文字**降级链路** + 质量字段标注 + 人工审核 | §4.5 |
| P8 | **需执行任意转换逻辑，又不能破坏信任边界**：不可信代码直接执行会带来任意文件/网络/资源风险 | **三层职责分离**——控制平面准入、隔离执行平面沙箱执行、内核重新哈希准入；“执行成功 ≠ 可信” | §3 / §5.5 |

> 说明：系统的能力**以代码为准**，只描述已落地、可被测试或运行验证的功能；每一项能力都能映射到上述某个痛点，避免“为做而做”。

## 3. 系统总体架构（完整全景）

### 3.1 设计理念：智能、执行与信任三者分离

系统最核心的架构决策，是把三件在传统方案里常常混在一起的事**彻底拆开**：

- **“写转换逻辑”**——由智能层负责，产出声明式的“数据产品契约”与受控的转换逻辑；
- **“隔离执行”**——由独立执行平面负责，在受控沙箱里安全地运行代码；
- **“判定可信”**——由数据内核负责，对执行产物重新校验、验证并决定能否发布。

> 三者统一的是**转换逻辑的接口约定与受控执行路径**，而不是取消信任门。这使得系统既能**扩展**（新的数据类型经同一条受控路径接入），又能保持“**可信只来自内核门禁**”的可靠性底线。

### 3.2 架构全景

```text
用户（自然语言研究主题）
   |
   v
前端界面（自然语言输入 / 步骤流 / 产物预览与下载）
   |
   v
应用宿主（统一入口：智能层 / 数据内核 / 接口 / 设置 / 前端托管，单一对外端口）
   |
   v
智能层（Agent）
   发现来源 / 检索示例
   编写「数据产品契约」（声明式，不含代码）
   编写「转换逻辑」（受控转换）
   提议语义决策
   |
   v
家庭管理平面（Family Host · 控制平面 / 准入）
   严格解析 / 计算摘要 / 作用域解析
   解析投影、模式、转换引用与策略
   准入 或 拒绝
   |
   v
变换执行平面（Transform Host · 隔离沙箱）
   编译并准入内容寻址代码包
   仅登记输入、有界读写、无网络
   资源配额 / 取消 / 超时 / 进程围栏
   产出：隔离区输出 + 执行回执
   |
   v
数据内核（Dataset Core · 产品信任平面）
   对执行平面输出重新哈希并准入
   兼容性分区 / 确定性整合
   大规模数据磁盘处理 + 科学验证 + 溯源闭环
   产品级评估
   原子发布（仅内核可发布）
   |
   v
标准化产物（清单文件驱动的 CSV 主表 / 辅助表 / 模式 / 溯源与审计材料）
```

### 3.3 各层职责边界

| 平面 | 负责什么 | 明确不做什么 |
| --- | --- | --- |
| **智能层** | 目标产品（数据产品契约）与候选转换逻辑；提议语义决策 | 不持有构建编排、发布器、发布阈值、网络或任意依赖权限 |
| **家庭管理平面** | 契约与转换逻辑的解析、摘要、作用域解析、准入/拒绝 | 不执行代码，不判定结果可信 |
| **变换执行平面** | 不可信代码**如何被隔离执行**（编译、沙箱、配额、隔离区输出） | 不决定结果是否可信 / 可发布 |
| **数据内核** | 输出**能否成为可信产品**（重哈希准入、验证、评估、原子发布） | 不执行智能层编写的代码 |

### 3.4 信任模型与安全边界

系统设定了几条**不可逾越的安全红线**，从机制上保证“不可信代码”无法破坏整体可信性：

- 代码级隔离手段（线程沙箱、脚本虚拟环境、同账户子进程）**均不能**单独充当不可信代码的安全边界；生产环境仅允许**独立低权限操作系统 / 容器沙箱**。
- 转换逻辑**不能**决定合并胜者、验证阈值、产品评估或发布动作。
- **只有数据内核**可以提交操作结果、构造发布候选并调用发布器。
- 变换执行平面执行成功**只产生隔离区输出与执行回执**，不代表结果可信或可发布；必须经内核重新哈希准入后才进入可信链路。

> 换言之：即使执行平面内出现缺陷或被滥用，也**不会直接污染**最终的可信产物。这是整个系统在“可扩展”与“可信”之间取得平衡的关键。

## 4. 核心能力设计

> 本节按能力组织，每项均映射到 §2 的对应痛点。

### 4.1 多源数据查找与获取（P1）

系统通过**可插拔的技能（Skill）+ 业务工具**访问多类生物医学数据源，并把“来源”与“来源关系”记录进任务。内置来源目录：

| 数据源 | 角色 | 说明 |
| --- | --- | --- |
| PubMed | 数据管线 | 文献检索，发现研究、提供来源关系 |
| GEO | 数据管线 | 基因表达、平台、探针映射、尺度与归一化兼容性 |
| GDC | 数据管线 | 癌症基因组（如 TCGA 级）数据 |
| Xena | 数据管线 | UCSC Xena 表达 / 元数据镜像 |
| Reactome | 研究辅助 | 通路成员（独立“通路成员”数据集族） |
| ChEMBL | 研究辅助 | 生物活性测量 |
| UniProt | 研究辅助 | 蛋白注释 |
| PDB | 研究辅助 | 蛋白结构（mmCIF 解析、结构距离 / 序列比对衍生） |
| PubChem | 研究辅助 | 化合物信息 |
| 本地缓存 / 文件 | 数据管线 | 本地缓存、本地源导入（CSV / TSV / JSON） |

> “**数据管线**”指该来源数据能进入受信任的内核摄取路径；“**研究辅助**”指作为智能体检索 / 研究能力使用（产物停在工作区 / 缓存），两类来源最终都汇入同一套可信内核。

系统覆盖 **6 个数据族**：基因表达、文献证据、靶点证据、变异证据、蛋白结构、生物活性测量。智能层另提供文献理解 / 文档抽取、网页视觉采集 + 图表数据抽取、浏览器自动化、科研数据处理通用指导等能力包。

### 4.2 数据解析、清洗与字段对齐（P2 / P3 / P5）——可靠性核心

系统**不依赖模型“猜字段”**，而是由**确定性数据内核**驱动一条七步流水线：

```text
1  获取        来源绑定 -> 下载 -> 校验（协议 / 域名 / 大小 / 超时 / 校验和）
2  解析        按来源适配器解析为数据批
3  归一化      字段映射、实体与单位规范化
               （字符串相似度只产生“候选提议”，须经适配器/模式/可信元数据/人工批准才进入正式合并）
4  兼容性门禁   数据族 / 行粒度 / 主键 / 测量 兼容，才允许合并
5  整合        确定性合并，含磁盘化去重（内嵌数据库临时表 + 资源上限）
6  验证        由服务端版本化“验证配置”驱动（而非提示词约束）
7  发布        通过验证才原子提升为不可变发布产物
```

- **多格式、多载体解析**：内置受信任适配器覆盖 GEO / GDC / Xena / 基因表达定量，将结构化数据解析为**不可变源资产**（带校验和 / 类型 / 大小校验）；由模式驱动支持 CSV / TSV / JSON 的严格表头、行宽与类型校验，**失败行进入审计拒绝记录**而非被静默丢弃。
- **字段对齐的反幻觉机制**：字符串相似度只产生“候选提议”，需适配器、模式、可信元数据或人工批准后，方可进入正式合并（见 §5.3）。
- **兼容才合并**：仅在数据族、行粒度、主键、测量都兼容时合并，避免“假整合”。
- **大表磁盘化**：去重 / 分组在内嵌数据库临时表上流式进行并受资源上限约束，避免内存溢出（见 §5.7）。

<!-- 图：确定性数据内核七步流水线示意图（转 HTML 时绘制） -->

### 4.3 数据质量处理（P6）

- **自动识别**缺失、重复、单位不一致等质量问题；
- **失败行进入审计**而非静默丢弃，保证“少一条数据”也能被解释；
- 对低置信度的图表数值做**坐标轴 / 图例校验**；
- 需要时**请求人工建议后再修正**（人在回路，见 §6）。

### 4.4 来源标注与可追溯性（P4）

- 每个构建的产物由**清单文件（Manifest）唯一权威声明**（程序不硬编码任何文件名）；
- 每条数据可经“源资产 / 定位符 / 适配器 / 解析器 / 配置引用”回溯到**原始来源与处理版本**（内容寻址 + 摘要）；
- 产物包含完整审计材料：来源清单、来源关系、下载日志、字段映射、处理日志、质量报告、拒绝记录与警告；
- **置信度可解释**（见 §6）。

### 4.5 图表 / 图像数据提取（P7）

- 可选使用**浏览器自动化**对网页 / 论文页面截图；
- 以**视觉大模型 / 文档解析 / 说明文字**组成**降级链路**提取图表数据（任一环节失败自动降级）；
- 提取产物带 `estimated`（估计值）、坐标轴不清、图例不清、待人工审核等**质量字段**，可复用持久化的人在回路 / 置信度协议做人工审核。

## 5. 创新点与设计亮点

> 本项目最核心的贡献，与其说是一项单点技术，不如说是一套**设计理念**：让 AI 只做“数据统合引擎的操作者”，而不做“数据的编写者”。围绕这一理念，我们用一系列**确定性、可信、可审计**的机制来对抗模型幻觉。通用 Agent 已不再稀缺，真正稀缺的是“**可信**”——这正是本项目的立足点。

### 5.1 创新点一：AI 是“引擎的操作者”，而非“数据的编写者”

AI 不直接产出或改写数据，只负责理解需求、发现来源、编写声明式“数据产品契约”与受控转换、提议语义决策；真正修改与组织数据的，是一组**确定性机制**。
**价值**：数据链路的行为与可信性**不随模型 / 提示词变化而漂移**——换模型、改提示词，都不会动摇数据的正确性与可审计性，输出准确性因此大幅提升。

### 5.2 创新点二：跨模态自动汇聚与统一建模

对接分散、异构的多个平台与多种数据载体（文献**文本** / 结构化**表格** / 论文**图表图像**），跨模态自动汇聚，并归一到**统一的规范数据模型**（6 个数据族）。
**价值**：把“人工跨库搬运 + 手工对齐”变成“自动汇聚 + 统一建模”，直接回应“数据割裂、格式异构、人工整合低效”的痛点。

### 5.3 创新点三：领域知识驱动的精准纠错与标准化

不用“通用规则一刀切”（易误删或留噪），而以**领域知识**（数据模式、单位与实体规范、兼容性约束）为依据做精准纠错与标准化；字符串相似度只产生“**候选提议**”，须经领域依据 / 可信元数据 / 人工批准才生效。
**价值**：纠错“有依据”，从机制上避免“长得像 = 同一字段”的静默错配，兼顾准确性与安全性。

### 5.4 创新点四：领域合理性校验，主动标记异常，降低伪阳性

内置**领域（生物学）合理性校验**，由服务端版本化“验证配置”驱动；**主动标记**缺失、重复、单位不一致、低置信度等异常，失败行进入审计而非静默丢弃，并给出**可解释置信度**（批次级 / 记录级）。
**价值**：把“研究者逐条手动甄别可信度”变成“系统主动标记 + 人工复核”，大幅降低伪阳性风险。

### 5.5 创新点五：写转换、隔离执行、判可信三者分离

把“写转换逻辑 / 隔离执行 / 判定可信”拆为三个独立平面，统一的是**转换接口与受控执行路径**，而非取消信任门。
**价值**：系统在保持“可信只来自内核门禁”的前提下实现**可扩展**——新数据类型经同一条受控路径接入，而信任边界不被削弱。

### 5.6 创新点六：全链路内容寻址溯源

数据一经摄取即被赋予“内容地址（哈希）”且不可变，产物统一由**清单文件**声明，每条数据可回溯到原始来源与处理版本。
**价值**：任何一条数据都能回答“来自哪、如何处理、哪个版本”，天然满足学术场景对可追溯、可复现的要求，也让“少了一条数据”这类问题可被定位与解释。

### 5.7 设计亮点（工程“小巧思”）

- **规范化摘要（内容标识对格式差异不敏感）**：同一份数据产品契约，即使字段顺序、别名、默认值、空白不同，也计算得到**相同摘要**——按“语义”而非“字面”识别同一对象，是去重、准入与复用的基础。
- **大表磁盘化去重**：大表去重 / 分组在内嵌数据库临时表上流式进行，配合资源上限与一致性校验，避免“把表全塞进内存”的溢出。
- **“执行成功 ≠ 可信”**：隔离执行产物先进“隔离区”并附“执行回执”，必须经内核重新哈希准入才可能成为可信产品——即使执行平面被滥用也不直接污染可信产物。
- **事件溯源的持久化运行时**：任务的权威事实是**持续追加的事件日志**，快照可由事件重建，中断 / 崩溃后可恢复、进度可重放；前端展示只是事件的“投影”，不是事实来源。

## 6. 数据质量与人在回路

系统把“人机协作”做成一等公民，而非事后补丁：

- **任务可暂停 / 继续**：等待用户输入（计划确认、数据修正、达到轮次上限等），状态持久化、可跨会话恢复；
- **细粒度权限系统**：智能层的文件访问与命令执行经“允许 / 询问 / 拒绝”三级控制，其中“询问”会**挂起单个工具调用**等待用户批准，并以持久化事件记录全过程；
- **人工修正闭环**：对低置信度或异常数据，系统**主动寻求人工建议后再修正**，修正过程留痕；
- **置信度可解释**：区分批次级与记录级置信度，视觉 / 语言模型抽取的结果要求记录级标注并进入人工审核，来源清晰可查。

## 7. 工程能力与运行支撑

- **统一应用宿主**：前端、智能层、数据内核、接口、设置与静态托管收敛在单一宿主、单一对外端口，拓扑简单、可测试、可验证；
- **实时交互**：前端以编码智能体风格的步骤流呈现用户输入、思维过程、工具调用、阶段、进度、警告与产物，支持断线重连并按持久化序号补齐事件；
- **模型与设置**：通过接口配置大模型，模型配置经注册表持久化（供应商 / 模型 / 激活状态入库，密钥独立存储且仅掩码返回）；模型快照在任务创建时形成**不可变配置**，避免并发变更影响已启动任务；
- **技能系统自迭代**：执行完成后把工具流还原为**可复用脚本候选 + 技能说明候选 + 分析报告**，沉淀复用经验，固化需人工评审。

## 8. 小结

BioMed-QAgent 围绕“**从科学问题到可用数据**”这一真实研究场景，构建了一套**可扩展、可追溯、可验证、可恢复**的智能数据检索与整合系统。它区别于“让大模型直接产出表格”的根本之处，在于**让 AI 只做“数据统合引擎的操作者”，而不做“数据的编写者”**，并进一步把**写转换、隔离执行、判可信三者分离**：智能层负责“理解与提议”，受控执行平面负责“安全地做”，数据内核负责“判定能不能信”。

由此，系统在满足赛题“**数据查找完备性、来源可追溯性、清洗整合可靠性、输出格式可用性**”四项核心要求的同时，进一步回应了科研场景对**可信、可复现、可解释**的深层需求——这正是本项目的设计价值所在。
