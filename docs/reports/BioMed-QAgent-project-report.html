01项目概述

BioMed-QAgent 是一个面向生物医学开放数据的智能检索与整合系统。用户只需用自然语言描述研究主题（例如“乳腺癌正常组织与肿瘤组织 GEO 转录组数据集整合”），系统即可自动完成查找来源 → 获取原始数据 → 解析、清洗与字段对齐 → 整合 → 产出带完整来源与审计信息的标准化表格的全流程，把“从科学问题到可直接分析的数据”这一研究场景自动化。

系统有一条贯穿始终的设计底线：让 AI 只做“数据统合引擎的操作者”，而不做“数据的编写者”：不靠模型“猜”出一张表格，也不在缺少数据证据时编造科研或临床结论。真正修改与组织数据的，是一系列确定性、可信、可审计的机制；每一份正式产物都必须经过确定性的验证门禁才会发布，每一条数据都能回答“它来自哪里、被怎样处理过、用的是哪个版本”。

02需求分析与痛点

本系统对应赛题“从科学问题到可用数据”的真实研究场景：系统的首要任务是构建标准化、可直接用于后续分析的可用数据集（以合并后的多源表格为核心产物），而非完成一项完整的研究。围绕这一目标，我们识别出以下核心痛点，并逐一对应到系统的设计方案。

#场景痛点对应的设计方案详见
P1 数据源分散、格式与标准不一：科学数据散落 PubMed、GEO、GDC 等数十个库与文献，无统一入口 多来源适配器 + 内容寻址“源资产” + 模式（Schema）驱动解析，统一汇入确定性内核 §3.1 / §4.1
P2 模型易“幻觉”字段与结论：大模型会“猜”字段含义、临时合并，缺证据时甚至编造结果，难以复现 确定性数据内核七步流水线；字段对齐靠规则 + 可信元数据，字符串相似度只产生“候选提议”；无证据不产出正式产物 §4.2 / §5.1 / §5.3
P3 多源数据不可直接合并：行粒度、主键、计量单位、表达体系各不相同，直接合并产生“假整合” 兼容性门禁：仅当数据族、行粒度、主键、测量兼容才允许合并；单位与表达规范化 §4.2
P4 来源难追溯、难验证：学术场景下每条数据须能回答“来自哪、如何处理、何版本”，否则无法复现引用 全链路溯源：内容寻址 + 摘要，清单文件为产物唯一权威，可回溯到原始来源与处理版本 §4.4
P5 数据质量问题缺乏系统处理：缺失、重复、单位不一致零散难处理 自动异常识别 + 失败行进入审计而非静默丢弃 + 人在回路“寻求人工建议后修正” §4.3 / §6
P6 需执行任意转换逻辑，又不能破坏信任边界：不可信代码直接执行会带来任意文件/网络/资源风险 三层职责分离：控制平面准入、隔离执行平面沙箱执行、内核重新哈希准入；“执行成功 ≠ 可信” §3 / §5.5

说明：系统的能力以代码为准，只描述已落地、可被测试或运行验证的功能；每一项能力都能映射到上述某个痛点，避免“为做而做”。

03系统总体架构（完整全景）

3.1 设计理念：智能、执行与信任三者分离

系统最核心的架构决策，是把三件在传统方案里常常混在一起的事彻底拆开：

  • “写转换逻辑”：由智能层负责，产出声明式的“数据产品契约”与受控的转换逻辑；
  • “隔离执行”：由独立执行平面负责，在受控沙箱里安全地运行代码；
  • “判定可信”：由数据内核负责，对执行产物重新校验、验证并决定能否发布。
三者统一的是转换逻辑的接口约定与受控执行路径，而不是取消信任门。这使得系统既能扩展（新的数据类型经同一条受控路径接入），又能保持“可信只来自内核门禁”的可靠性底线。

3.2 架构全景

3.3 信任模型与安全边界

系统设定了几条不可逾越的安全红线，从机制上保证“不可信代码”无法破坏整体可信性：

安全红线
  • 代码级隔离手段（线程沙箱、脚本虚拟环境、同账户子进程）均不能单独充当不可信代码的安全边界；生产环境仅允许独立低权限操作系统 / 容器沙箱。
  • 转换逻辑不能决定合并胜者、验证阈值、产品评估或发布动作。
  • 只有数据内核可以提交操作结果、构造发布候选并调用发布器。
  • 变换执行平面执行成功只产生隔离区输出与执行回执，不代表结果可信或可发布；必须经内核重新哈希准入后才进入可信链路。
换言之：即使执行平面内出现缺陷或被滥用，也不会直接污染最终的可信产物。这是整个系统在“可扩展”与“可信”之间取得平衡的关键。

04核心能力设计

本节按能力组织，每项均映射到 §2 的对应痛点；4.5 多模态图表抽取为数据载体扩展能力。

4.1 多源数据查找与获取（P1）

系统通过可插拔的技能（Skill）+ 业务工具访问多类生物医学数据源，并把“来源”与“来源关系”记录进任务。内置来源目录分两类：数据管线（数据进入受信任的内核摄取路径）：PubMed 文献检索、GEO 表达与探针映射、GDC 癌症基因组、Xena 镜像、本地缓存与本地文件导入（CSV / TSV / JSON）；研究辅助（作为智能体检索 / 研究能力使用，产物停在工作区 / 缓存）：Reactome 通路成员、ChEMBL 生物活性、UniProt 蛋白注释、PDB 蛋白结构、PubChem 化合物信息。两类来源最终都汇入同一套可信内核。

系统覆盖 6 个数据族：基因表达、文献证据、靶点证据、变异证据、蛋白结构、生物活性测量。智能层另提供文献理解 / 文档抽取、网页视觉采集 + 图表数据抽取、浏览器自动化、科研数据处理通用指导等能力包。

4.2 数据解析、清洗与字段对齐（P2 / P3）· 可靠性核心

系统不依赖模型“猜字段”，而是由确定性数据内核驱动一条七步流水线：

  • 多格式、多载体解析：内置受信任适配器覆盖 GEO / GDC / Xena / 基因表达定量，将结构化数据解析为不可变源资产（带校验和 / 类型 / 大小校验）；由模式驱动支持 CSV / TSV / JSON 的严格表头、行宽与类型校验，失败行进入审计拒绝记录而非被静默丢弃。
  • 字段对齐的反幻觉机制：字符串相似度只产生“候选提议”，需适配器、模式、可信元数据或人工批准后，方可进入正式合并（见 §5.3）。
  • 兼容才合并：仅在数据族、行粒度、主键、测量都兼容时合并，避免“假整合”。

4.3 数据质量处理（P5）

  • 自动识别缺失、重复、单位不一致等质量问题；
  • 失败行进入审计而非静默丢弃，保证“少一条数据”也能被解释；
  • 对低置信度的图表数值做坐标轴 / 图例校验；
  • 需要时请求人工建议后再修正（人在回路，见 §6）。

4.4 来源标注与可追溯性（P4）

  • 每个构建的产物由清单文件（Manifest）唯一权威声明（程序不硬编码任何文件名）；
  • 每条数据可经“源资产 / 定位符 / 适配器 / 解析器 / 配置引用”回溯到原始来源与处理版本（内容寻址 + 摘要）；
  • 产物包含完整审计材料：来源清单、来源关系、下载日志、字段映射、处理日志、质量报告、拒绝记录与警告；
  • 置信度可解释（见 §6）。

4.5 多模态图表数据抽取（数据载体扩展）

  • 可选使用浏览器自动化对网页 / 论文页面截图；
  • 以视觉大模型 / 文档解析 / 说明文字组成降级链路提取图表数据（任一环节失败自动降级）；
  • 提取产物带 estimated（估计值）、坐标轴不清、图例不清、待人工审核等质量字段，可复用持久化的人在回路 / 置信度协议做人工审核。

05创新点与设计亮点

本项目最核心的贡献，与其说是一项单点技术，不如说是一套设计理念：让 AI 只做“数据统合引擎的操作者”，而不做“数据的编写者”。通用 Agent 已不再稀缺，真正稀缺的是“可信”。本项目并未发明某种新机制，而是把流水线、沙箱、清单这些成熟工程手段组织成“谁写、谁执行、谁判可信”职责分离的信任架构，使数据链路的行为与可信性不随模型更换或提示词变化而漂移。
01

AI 是“引擎的操作者”，而非“数据的编写者”

AI 不直接产出或改写数据，只负责理解需求、发现来源、编写声明式“数据产品契约”与受控转换、提议语义决策；真正修改与组织数据的，是一组确定性机制。

价值数据链路的行为与可信性不随模型 / 提示词变化而漂移：换模型、改提示词，都不会动摇数据的正确性与可审计性，输出准确性因此大幅提升。

02

跨模态自动汇聚与统一建模

对接分散、异构的多个平台与多种数据载体（文献文本 / 结构化表格 / 论文图表图像），跨模态自动汇聚，并归一到统一的规范数据模型（6 个数据族）。

价值把“人工跨库搬运 + 手工对齐”变成“自动汇聚 + 统一建模”，直接回应“数据割裂、格式异构、人工整合低效”的痛点。

03

领域知识驱动的精准纠错与标准化

不用“通用规则一刀切”（易误删或留噪），而以领域知识（数据模式、单位与实体规范、兼容性约束）为依据做精准纠错与标准化；字符串相似度只产生“候选提议”，须经领域依据 / 可信元数据 / 人工批准才生效。

价值纠错“有依据”，从机制上避免“长得像 = 同一字段”的静默错配，兼顾准确性与安全性。

04

领域合理性校验，主动标记异常，降低伪阳性

内置领域（生物学）合理性校验，由服务端版本化“验证配置”驱动；主动标记缺失、重复、单位不一致、低置信度等异常，失败行进入审计而非静默丢弃，并给出可解释置信度（批次级 / 记录级）。

价值把“研究者逐条手动甄别可信度”变成“系统主动标记 + 人工复核”，大幅降低伪阳性风险。

05

写转换、隔离执行、判可信三者分离

把“写转换逻辑 / 隔离执行 / 判定可信”拆为三个独立平面，统一的是转换接口与受控执行路径，而非取消信任门。

价值系统在保持“可信只来自内核门禁”的前提下实现可扩展：新数据类型经同一条受控路径接入，而信任边界不被削弱。

5.6 设计亮点

规范化摘要（内容标识对格式差异不敏感） 同一份数据产品契约，即使字段顺序、别名、默认值、空白不同，也计算得到相同摘要：按“语义”而非“字面”识别同一对象，是去重、准入与复用的基础。
“执行成功 ≠ 可信” 隔离执行产物先进“隔离区”并附“执行回执”，必须经内核重新哈希准入才可能成为可信产品；即使执行平面被滥用也不直接污染可信产物。
事件溯源的持久化运行时 任务的权威事实是持续追加的事件日志，快照可由事件重建，中断 / 崩溃后可恢复、进度可重放；前端展示只是事件的“投影”，不是事实来源。

06数据质量与人在回路

系统把“人机协作”做成一等公民，而非事后补丁：

  • 任务可暂停 / 继续：等待用户输入（计划确认、数据修正、达到轮次上限等），状态持久化、可跨会话恢复；
  • 细粒度权限系统：智能层的文件访问与命令执行经“允许 / 询问 / 拒绝”三级控制，其中“询问”会挂起单个工具调用等待用户批准，并以持久化事件记录全过程；
  • 人工修正闭环：对低置信度或异常数据，系统主动寻求人工建议后再修正，修正过程留痕；
  • 置信度可解释：区分批次级与记录级置信度，视觉 / 语言模型抽取的结果要求记录级标注并进入人工审核，来源清晰可查。

07工程能力与运行支撑

  • 统一应用宿主：前端、智能层、数据内核、接口、设置与静态托管收敛在单一宿主、单一对外端口，拓扑简单、可测试、可验证；
  • 实时交互：前端以编码智能体风格的步骤流呈现用户输入、思维过程、工具调用、阶段、进度、警告与产物，支持断线重连并按持久化序号补齐事件；
  • 技能系统自迭代：执行完成后把工具流还原为可复用脚本候选 + 技能说明候选 + 分析报告，沉淀复用经验，固化需人工评审。

08小结

BioMed-QAgent 围绕“从科学问题到可用数据”这一真实研究场景，构建了一套可扩展、可追溯、可验证、可恢复的智能数据检索与整合系统。它区别于“让大模型直接产出表格”的根本之处，在于让 AI 只做“数据统合引擎的操作者”，而不做“数据的编写者”，并进一步把写转换、隔离执行、判可信三者分离：智能层负责“理解与提议”，受控执行平面负责“安全地做”，数据内核负责“判定能不能信”。

由此，系统在满足赛题“数据查找完备性、来源可追溯性、清洗整合可靠性、输出格式可用性”四项核心要求的同时，进一步回应了科研场景对可信、可复现、可解释的深层需求。
