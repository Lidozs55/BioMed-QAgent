Dataset Core 是系统唯一的数据信任边界。它将数据处理固定为八个阶段：采集、解析、规范化、兼容性检查、整合、多表组装、校验、发布。每个阶段都有明确的输入、输出摘要和执行凭证，说明该阶段做了什么、产生了哪些文件及各文件的摘要。本章按阶段说明Core对数据质量做了什么，机制细节随项目资料保留。

Agent 的自主决策面见 \ref{sec:agent-autonomy} 节。决策进入 Core 后，执行路线固定，正式数据值由注册操作产出。动态数据家族允许 Agent 提供的变换代码在一个受限执行区内产生候选字节；这些候选要成为正式数据，必须依次通过准入检查、完整性校验、多表产品评估与发布器的逐级检查。准入检查核对输入、输出与摘要是否精确闭合，任何一级不通过即整体拒绝。动态家族扩展的是“能读什么”，不扩大“能写什么”。写入侧的约束是结构性的：准入检查不验证变换代码的语义正确性，计算错误的变换同样能通过检查，数值语义依赖事后抽查。这背后是系统的核心权衡：可靠性来自预置的注册表、解析器与校验规则，覆盖的开放性由动态路线承担，语义正确性的保障相应从预置代码转移到变换审查与事后抽查。表结构设计、字段映射与变换代码由 Agent 在运行时提出，经与内置路线相同的准入与校验通道后成为正式数据。

详图展开 Core 内部的两条路线。A 路线使用已注册数据家族的固定操作骨架；B 路线处理动态规格：变换方只交付候选字节，隔离区和 Core 再通过重新计算摘要、检查闭合条件等方式统一校验。变换方不能选择校验、评估或发布模块；\ref{sec:contributions} 节所述运行时表结构准入控制即以这一隔离为基础。变换产出的表头哪怕只与声明相差一个字段，隔离区也会以 \code{OUTPUT\_\allowbreak{}HEADER\_\allowbreak{}MISMATCH} 拒绝该候选。占位符空壳是内容筛查上线前唯一一次穿透到发布的案例，上线后未再发生。系统还用明确的结束状态区分“运行完成”和“正式发布”：终态分为 Rejected、NO\_\allowbreak{}DATA、Failed 与 Cancelled 四类，拿不准就拒绝。

\section{阶段 1：正式采集与来源资产登记（acquire）}

Agent 的来源发现拿到 URL 后，正式路线不会直接信任工作区中的任意文件。Core 的统一下载设施按预定的请求定义执行网络访问，实施访问策略、大小与超时限制、重试、断点续传和内容缓存。文件写入任务专属目录后，来源资产注册表流式计算 SHA-256，把任务、来源身份、内容摘要、媒体类型与采集实现身份绑定为一份输入证据，支持时还记录快照或修订号等版本信息。因此，“来源资产”不是一个本地路径，而是可复核的输入证据。

\section{阶段 2：异构数据解析（parse）}

正式静态路线使用已注册的解析器，把来源特有的 CSV、JSON、XML、XLSX、SOFT、矩阵或 API 响应转换为数据批次，同时输出解析统计、被拒绝的记录和溯源定位信息。解析器的原则是\textbf{失败而不猜测}：遇到来源格式异常时，解析器应失败或将问题写入审计记录，而不是让模型猜测缺失字段。

表达数据的解析集中体现了行层级纪律。GEO 既可能提供基因级结果，也可能只提供探针级矩阵；系统不会在缺少可信注释时把探针当成基因，一行究竟代表一个探针还是一个基因由表结构显式声明。GDC 与 Xena 的输入形态不同，但都必须转换到目标表达表结构后才可合并。

论文衍生的载体单独处理。PDF 表格解析保留页面与位置证据（页码、边界框、题注），无框线表格与跨页表头仍是启发式解析难点，这类解析结果需人工核对。图表走视觉模型通道（\ref{subsec:chart-vlm} 节）。

\subsection{图表与视觉模型}\label{subsec:chart-vlm}

赛题要求的“自动识别图表坐标轴或图例解析错误”由确定性规则层承担。图表工具采用多层降级策略：系统优先通过 \code{qwen3.8-flash} 理解页面图像或嵌入图像；失败后尝试解析 PDF 表格；再次失败时，只提取图表标题作为有限信息。“失败”指模型调用或解析出错；返回内容格式正确但数值错误时不触发降级，由点级复核与置信度门禁兜底。模型抽取结果必须携带模型名；图表中每个数据点的抽取结果还必须包含置信度及其判定原因。其可信级受 \ref{sec:stage7-validate} 节所述确定性上限的约束，不会因为模型自报高可信（high）就自动成为正式真值。

就规范侧而言，已落地的链路是：视觉语言模型（VLM）、PDF 表格或标题抽取的结果先作为结构化图表证据（chart-evidence）进入系统，形成带点级取值与来源绑定的证据资产，再进入生产环境的 bioactivity\_\allowbreak{}measurement 数据家族。样例6 的正式发布包含活性值、实验、论文、补充资产、图系列与图点 6 个数据表，另有表结构、溯源与质量评估，共 9 件产物。组装前，系统逐点核对来源并复核证据，无法确认的图表数据不纳入正式数据。复核未通过时，系统写入结构化 \code{chart\_\allowbreak{}evidence\_\allowbreak{}gate} 检查结果并阻止发布，不会让任意工作区 CSV 直接获得正式发布权。人工修正保留原始值，并记录 human\_\allowbreak{}correction 处理步骤；样例6 实验中的 5 次人工确认包括 3 次受控来源访问授权和 2 次发布验收。

\code{chart\_\allowbreak{}series} 表记录轴名、轴单位与刻度和图例文本，并须声明轴/\allowbreak{}图例校验状态（clear /\allowbreak{} unclear /\allowbreak{}
human\_\allowbreak{}validated）。系统用确定性规则核对轴/图例声明状态与点数据的一致性：声明为 exact 的点一旦对应轴或图例含义 unclear 即直接判失败；系列允许省略点数据的唯一条件是轴或图例状态明确标为 unclear。轴/图例状态由抽取模型声明，该规则覆盖“声明与点数据不一致”一类错误；状态被误报为 clear 时不在此范围内。这条链路已有点级的样例完成测试。无论采纳（accepted）还是人工修正（corrected），两条路径都产出正式发布物并逐件重算 SHA-256；未经复核或缺表的运行不产生任何发布物。

\section{阶段 3：含义规范化与缺失、重复处理（normalize）}

规范化器依据目标表结构完成类型转换、字段命名统一、实体标识表达和必要的值标准化。核心原则是：只有目标表结构和规范化配置明确授权的变化，才可以自动执行；规范化过程保留原始写法与规范值之间的血缘，便于任何一处转换被事后复核。

缺失与重复按类型分层处理：必填字段缺失时拒绝或阻断，可选字段缺失保留为空并计入完整性统计；完全重复按确定性键去重；主键重复且值一致时合并血缘、保留多来源。每类处理都保留对应证据，以便后续复核。

实体身份对齐同样采用确定性机制：化合物以 InChI Key 精确匹配建立交叉映射表，匹配不上时显式标记为冲突而不强行合并；基因符号归一使用内置确定性映射表；探针到基因的映射依赖逐平台注释资产，未映射探针保留原命名空间，不静默丢弃。这些注释资产与来源文件同样按内容摘要登记，映射结果随发布件交付。

\section{阶段 4--5：兼容性检查与多源整合（compat、integrate）}\label{sec:stage5-integrate}

解析与规范化产物进入整合前，兼容性检查核对各批次在数据家族、表结构、行层级、实体层级、单位、含义和尺度上是否可以合并，并据此生成确定性的合并域键：值的含义、尺度与单位，加上物种、特征命名空间、测量类型、规范化状态与参考版本等维度，任何一维不一致都不能进入同一合并域。未知单位或不受支持的数值尺度不会被自动修正；单位换算只在有注册转换公式时执行，公式限定为线性安全形式，没有注册规则时阻断或交人工选择——系统不自动“猜”一个换算。

整合器按注册的合并策略合并批次，并在最终来源权威行上汇总血缘和置信度。主键重复且值冲突时保留来源权威行并写冲突审计，必要时阻断；实体身份冲突保留交叉映射表；值一致时合并血缘并保留双来源标记。真正需要“二选一”的少数同键冲突，采用先到优先作为可复现的终局裁决，落选来源、冲突键与裁决依据写入审计随产物交付——最终取哪个值为真，显式留给研究者复核或改判。整合层的产出是“可复核的记录”，而不是替研究者定案。

\section{阶段 6：多表组装（derive）}\label{sec:stage6-derive}

对于需要多实体关系的数据，数据家族的组装阶段生成多表候选，并检查主键、外键、基数和表角色。\footnote{主键：表中每行的唯一标识。外键：表中指向另一张表主键的字段，如测量表中的化合物编号指向化合物表。基数：两表间一条记录与另一表几条记录的对应关系。表角色：各表分别承担记录测量值还是提供规范身份。}

单表与多表是规格层的可选形态。需求是单一层级观察时交付单表，例如样例8 的 FAERS 不良事件计数；需求横跨多个实体层级时才拆分多表。以生物活性数据为例，测量值表（activities）按声明的外键关联实验条件表（assays）与化合物规范身份表（compounds），并辅以靶点表、来源表与交叉映射表（图~\ref{fig:bioactivity-fk}），避免把不同层级的观测压进重复严重的宽表。多表发布清单记录表、关系、溯源引用和置信度引用，下游按清单声明的显式关系连接各表，而不是凭同名列猜测连接键。

\section{阶段 7：校验、置信度与产品评估（validate）}\label{sec:stage7-validate}

校验配置在发布前检查候选结果，范围包括表结构与字段类型、必填字段完整性与允许缺失率、主键唯一性与外键基数、实体标识命名空间、单位与数值尺度、溯源与来源定位覆盖、置信度记录与最终行对齐、产物摘要闭合，以及可复现所需的输入与实现身份。多表产品评估从结构、关系、标识、溯源、置信度和可复现性六个维度评价产品：无阻断项时判定为“可发布”；只存在可复现性阻断项时至多为“已验证”；存在内容维度阻断项时判定为“不完整”。这使得“CSV 能打开”与“数据产品含义上闭合”不再是同一件事。

置信度按证据类型受到上限约束。确定性、受版本约束的解析可以获得包括 high 在内的较高可信等级；VLM、LLM、OCR 和网页抽取等非确定性来源最高封顶为 medium，并可按记录进入人工审核。封顶为 medium 的记录不自动进入人工审核：图表审核仅对低置信度记录发起（\ref{sec:hil} 节），medium 置信度的 VLM 数值可不经人工复核进入正式发布，准确性由事后来源级抽查保障。系统关注的是“该记录由何种证据和处理产生”，而不是让模型自由输出一个看似精确的概率。

验证结论与明确的结束状态绑定。空主数据、兼容性失败或验证失败的结果一律不可发布；“运行完成”也不等于“发布物生成”。

\section{阶段 8：不可变发布与消费时重验（publish）}\label{sec:stage8-publish}

发布器把质量检查合格的候选复制到独立目录，生成发布清单，逐文件记录相对路径、媒体类型、字节数和 SHA-256；发布经临时目录原子切换完成，执行锁与代次围栏保证超时或已取消的旧执行不能晚到覆盖新结果。产品 API 在每次读取时重新核验清单与文件摘要，文件被改动或损坏即拒绝展示。这里的“不可变”是应用层语义：正常 API 只追加发布、不覆盖旧版本；系统不提供抵御同一操作系统账户重写文件系统的密码学防篡改能力。

\section{持久化人工确认与可恢复执行（Durable HIL）}\label{sec:hil}

人工确认（Human-in-the-Loop, HIL）不是系统的第一反应，而是在确定性规则无法解决问题时使用的兜底环节。遇到模糊字段映射、未知单位或低置信度图表点等情况，Core 先尝试注册的确定性规则和候选推理；只有无法安全定案时，才创建结构化请求。例如，单位换算先查询注册公式表，命中后自动应用，不进入人工确认；只有不存在可用规则时才暂停。图表审核也只针对低置信度记录发起。
请求携带逐项候选值（proposed\_\allowbreak{}value）、置信度（confidence\_\allowbreak{}level）、相关记录、证据摘要以及任务/\allowbreak{}运行/\allowbreak{}需求身份。前端以“在候选与证据概要上选择”为主，以自由修正为辅（approve /\allowbreak{} reject /\allowbreak{} correct）。只有证据摘要和任务身份都匹配时，响应才能恢复原操作。

典型场景包括字段映射存在多个候选、未知单位或测量含义、探针到基因映射的歧义、低置信度图表点的确认，以及冲突记录需指定保留策略等。

按审批对象划分，人工确认覆盖三类：工具许可与凭据授权（approve/\allowbreak{}reject）、数据审核（字段映射、单位、图表与网页证据）和发布验收。对于需要验收的高风险产品（动态发布、图表证据、浏览器证据接受），发布验收不可绕过；只有人工 accept 后系统才执行发布。普通静态数据发布不统一要求发布验收类 HIL，这与“Core 独占发布权”相互配合。

审批档位按对象配置。每类审批范围可设为人工审批（\code{human\_\allowbreak{}review}）、LLM 初审（\code{llm\_\allowbreak{}pre\_\allowbreak{}review}，仅不通过项上报人工）或显式自动通过（\code{auto\_\allowbreak{}approve}）。初审不通过或模型调用失败时一律回退人工；涉及发布验收的对象强制人工审批，配置其他档位会被直接拒绝。低风险确认可以配置自动放行，高风险场景始终由人工处理。
