\section{案例评测协议与总览}\label{sec:eval-protocol}

为保证结果可复核，重点案例遵循同一评测协议：Agent 的输入只有案例需求原文（数百字节的研究需求描述，不含任何参考答案或人工整理数据），代码冻结在单一版本；由独立的外部监督程序驱动任务，把事件流持久化落盘，对发布产物逐件重新下载并重算字节与 SHA-256，最终给出三类终态判定（成功发布 / 未发布阻塞 / 失败或取消）。

评测模型为 DeepSeek-V4-Flash（上下文窗口 1,000,000、最大输出 32,768、温度 0.2）——选择一个非 Qwen 的国产模型是为了验证系统的模型无关性。Qwen 侧能力并非空白：此前 gold8 已在同链路上取得 Qwen3.8-27B 的同类正式发布，Qwen-VL
承担图表理解链路（\ref{subsec:chart-vlm} 节），全模型谱系的行为分层见 \ref{sec:multimodel} 节。另需说明时间线：重点案例的代码冻结早于占位符内容筛查的落地，但三案例产物均在筛查落地后经监督程序逐件 SHA-256 重验，与参考集的结构对照见

\textbf{过程要点}：Agent 首步调用路线检查（\code{inspect\_\allowbreak{}dataset\_\allowbreak{}execution\_\allowbreak{}routes}），确认静态注册表无任何数据家族能表达该三表拓扑后选择动态路线；随后经治理工具完成采集——GWAS

\section{案例 gold8：DILI 风险药物证据整合（来源失效下的正确终态）}\label{sec:gold8}

\textbf{输入（需求摘要）}：针对 DILIrank 2.0 vMost 药物整合三类证据——DILIrank 标签注释、LiverTox 专论、openFDA FAERS 肝毒性 PT 报告计数，约 50 种代表药、四表交付。

\textbf{关键难点与行为}：DILIrank 2.0 官方文件（\code{fda.gov/\allowbreak{}media/\allowbreak{}113052/\allowbreak{}download}）持续 404，LiverTox 无药物级结构化导出。
系统的处理展示了赛题“自动识别缺失数据……完成修正或寻求人类建议”加分项的完整链路：第一轮运行在发现阶段确认官方来源不可达后\textbf{未编造任何行}，以工作区暂存 +\allowbreak{} 结构化阻断收尾，明确请求“提供官方文件或注册 Core 资产”；第二轮定向续跑把可达维度（FAERS 计数）
正式化——9 个已验证药物各经一条 \code{openfda.files.v1} Core 采集绑定\textbf{重新获取}（发现阶段的查询输出不被当作正式载体），以动态数据家族发布。

这一“核实不可达 → 显式阻断 → 定向续跑 → 正式化可达维度”的降级链，正是提案加分项“自动识别缺失数据并完成修正或寻求人类建议”在数据链路上的落地；不可达维度的替代源自动发现为已识别的改进方向（\ref{sec:boundaries} 节边界 2）。

\textbf{输出结构}：\code{faers\_\allowbreak{}reaction\_\allowbreak{}counts.csv} 68 行 × 5
列（\code{drug\_\allowbreak{}name, reaction\_\allowbreak{}pt, report\_\allowbreak{}count, retrieval\_\allowbreak{}method, source\_\allowbreak{}url}）。请求的 9 药 × 8
肝毒性 PT = 72 行中，4 行因官方聚合响应确无该 PT 词条而\textbf{未零填充}，逐条列出（如 azathioprine–HEPATOCELLULAR INJURY）；其余 68 行与发现阶段 openFDA 计数逐条一致（如 acetaminophen ACUTE HEPATIC FAILURE =
3297）。

校验 16/\allowbreak{}16 通过（0 坏行、0 重复主键）、溯源 9/\allowbreak{}9 载体满足、\code{product\_\allowbreak{}status=publishable}。每行 \code{source\_\allowbreak{}url} 直接给出可复核的官方
API 查询串；\code{report\_\allowbreak{}count} 的语义为 MedDRA PT 报告次数（非去重患者、非因果证据），已在终答与溯源中注明。
不可达的 DILIrank vMost 名册与 LiverTox 维度不进入正式发布，仅保留为明确标注暂存的工作区文件——“部分维度正式发布 +\allowbreak{} 不可达维度结构化阻断”是该上游条件下的完成形态，也是 \ref{sec:stage7-validate} 节显式终态语义的一次实战兑现。
需要说明的是，这里的阻断并非“不做替代”：第三方镜像或转载无法进入字节级证据链，系统因此不会自动改换来源，而是结构化地请求研究者提供官方文件。

可靠的替代源自动发现（从文献补充或其他官方通道补 DILI 证据）已列为规划中的合规扩展。其余边界见 \ref{sec:boundaries} 节。

\section{结构化输出样例与字段说明}\label{sec:samples}

以 gold9 跨源证据交叉表为例（真实发布行）：
\begin{lstlisting}[style=papercode]
hgnc_symbol,orphacode,clingen_classification,clingen_classification_date,clingen_disease_label,clinvar_count,clinvar_query,conflict_flag,conflict_detail
TBX1,567,,,,,,NONE,
\end{lstlisting}

字段语义：\code{clingen\_\allowbreak{}classification} 为 ClinGen 基因-疾病有效性分类（Definite/\allowbreak{}Strong/\allowbreak{}Limited；Refuted/\allowbreak{}Disputed 出现时触发冲突逻辑）
；\code{clinvar\_\allowbreak{}count} 为 ClinVar 致病记录计数，\code{clinvar\_\allowbreak{}query} 保留实际查询串供复核；\code{conflict\_\allowbreak{}flag} 取 \code{NONE} 或
\code{CONFLICT\_\allowbreak{}CLINGEN\_\allowbreak{}REFUTED\_\allowbreak{}OR\_\allowbreak{}DISPUTED\_\allowbreak{}WITH\_\allowbreak{}ORPHANET\_\allowbreak{}ASSOCIATION}。
空值即“来源未覆盖该单元格”，系统不以零或推断填充（gold9 中两列整体为空的边界说明见 \ref{sec:boundaries} 节）。

输入侧同理：一个来源凭据不是“一个下载文件”，而是任务、来源、字节摘要与采集实现身份共同绑定的证据对象（来源凭据逐条登记）；发布清单对每个文件登记路径、字节数与 SHA-256，读取端每次读取都重算摘要，文件被改动即拒绝展示。
