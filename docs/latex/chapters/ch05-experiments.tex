\section{实验设计总览与评测方法}\label{sec:eval-protocol}

主评测六个运行单元冻结在同一产品提交 \code{e5aadfe0...203ba3}，由外部监督程序保存事件流、closure、发布清单和 Artifact API 回执，并对正式产物逐件重算大小与 SHA-256。运行时长统一取权威事件流中 \code{run\_started} 到终态事件的区间；token 取 \code{context\_usage} 聚合并与 closure 对账。终态分为成功发布、未发布阻塞、失败或取消。摘要校验只证明文件字节与回执一致，不单独证明科学正确性或需求覆盖完整。

提示词来源并不统一：gold6 flash 与 gold6 max v2 使用同一 exact-data 冻结 lineage；gold9 使用从历史 durable event 恢复的原始 \code{run\_queued.input}；gold7、gold8 与 gold10 使用重建的历史 \code{TOPIC} 文本。gold1--5 又来自更早的 flash 批次。因此只能在各自冻结范围内报告观察结果，不能把十个案例视为同一随机化或重复测量协议。主评测模型为 \code{qwen3.8-flash} 与 gold6 的 \code{qwen3.8-max-0902} 修正版；max v2 的 1M context / 32K output 元数据修正及代理 Host 条件也必须作为比较限制披露。

Qoder 侧的 Gold6 材料是两份离线导出 zip。当前已提交证据可复核其 CSV 结构、清单和部分 QC，但不含原始 payload、提取脚本，也不含可独立核验的会话时长或 provider token 导出。因此 Gold6 的跨环境部分只作产物审计，不从旧表中的平台时长/token 推导效率或机制因果结论。

\section{分层对照设计与可比性边界}\label{sec:factorial-design}

本节整理 gold1 与 gold6、flash 与 max、BioMed QAgent 与 Qoder 的八个观察单元，但不将其称为受控全因子实验。每个单元只有一次运行，没有重复、方差或显著性估计；跨环境提示词附加约束、默认推理参数、运行驱动与产物身份不同。该设计适合描述观察到的成本和产物差异，不支持把差异因果归因于某一个环境机制。

\textbf{观察单元选择}。gold1 与 gold6 分别代表数据库型表达组学任务和文献/图表型活性证据任务；flash 与 max 是各环境记录中的模型档位标签。该选择覆盖两种来源形态，但没有随机抽样，也未证明能代表全部十类任务。尤其 Qoder 离线包没有冻结可独立核验的完整模型配置，故模型档位只用于描述文件来源，不作稳健性推断。

\textbf{两种环境的输入构成}（关键事实，实验执行前冻结）：

\begin{itemize}
\item \textbf{BioMed QAgent}：用户输入只有 \code{TOPIC.txt} 原文（唯一合法任务输入）；赛题的各项要求不由用户消息携带，而是落实到系统提示词、治理工具与验证规则中。运行由监督程序驱动，事件流、token 用量与产物 SHA-256 自动落盘。
\item \textbf{Qoder}：用户输入为 \code{TOPIC.txt} 原文，加上赛题原文要求约束（附加条件与“应该完成的工作”原文），以单条用户消息给出；运行由人工在 Qoder 内发起；网络与 Python（pandas/numpy/scipy）可用。
\end{itemize}

gold1 在 Qoder 侧的完整输入原文如下，前半段为 \code{TOPIC.txt} 原文，其后为赛题原文要求约束；gold6 按同一构成规则生成，随实验执行一并冻结。

\begin{keypoint}[gold1 · Qoder 侧输入原文]
主题：乳腺癌正常组织与肿瘤组织 GEO 转录组数据整合

查找公开的人类乳腺癌 GEO 转录组数据，研究对象为乳腺癌肿瘤组织与对应正常乳腺组织，希望能通过两组样本的基因表达比较得出差异表达。汇总所获研究的样本元数据、平台注释与表达数据（含探针与基因水平的对应），整理成便于后续分析的数据文件。

---

附加条件：仅将 CSV 文件作为正式产出

你应该完成的工作是：查找相关论文、开放数据库、表格、补充材料和图像数据，从正文、表格、附件或图表中提取可用信息，并整理输出合并后的多源 CSV 表格；完成数据清洗、字段对齐、来源标注和结构化输出；如涉及论文图像或图表，还应能够说明图表数据的识别、提取或校验方式。
\end{keypoint}

\textbf{控制变量与披露}。同一案例的主题文本跨环境保持一致，但 Qoder 用户消息额外包含赛题要求；模型推理参数采用各环境默认值，运行也分别由监督程序与人工会话驱动。因此“环境”同时混合了提示词构成、运行管理与工具约束，不能被解释为单一处理因素。每个单元仅运行一次，不提供随机波动或显著性估计。

对四个运行单元的产物有以下观察：

（1）交付形态。Qoder 每个研究输出一张宽表：一行是一个探针或基因，一列是一个样本，可以直接读入 R 或 Python。BioMed QAgent 发布的是长表：每个样本的每个探针或基因各占一行，并附带来源定位列，行数因此大两个数量级。两边的数据来自同样的 GEO 原始文件，区别在于表格为谁而做：宽表面向研究者直接使用，长表面向程序逐行核验。

（2）纳入研究数。历史记录中 Qoder flash 纳入 16 个研究，BioMed QAgent flash 发布 1 个、max 发布 2 个。该差异可能同时受来源选择、运行预算、Agent 决策、验证门禁和交付定义影响；当前没有消融实验，不能归因于某一机制。

（3）差异表达覆盖不同。题目要求通过两组样本比较得到差异表达；历史四组中只有 Qoder flash 交付了单研究差异分析和跨研究 meta 分析。BioMed QAgent 两档交付了带肿瘤/正常分组的表达表，但本次运行没有执行比较。该结果是运行级缺口，不应上升为系统永久不支持统计分析的边界。

（4）审计机制。Qoder 以来源 URL、文件 MD5 和检索日期支持人工抽查；BioMed QAgent 以来源定位、资产摘要和 Publication 回执支持机器核验。两者的证据形态不同，摘要匹配均不等价于值级真实性；当前只能说已记录的抽样未报告冲突。

核验结果也显示了 BioMed QAgent 的几个实际优势：

\begin{itemize}
\item 质量检查内建在发布之前。每次构建自动执行编码、数值类型、单位一致、行边界、溯源完整性等十项检查并留下报告；Qoder 侧的质量控制是人工填写的方法日志，两者约束力不同。
\item 在已抽查的示例中，Qoder flash 的基因矩阵显示为 3 位小数，BioMed QAgent 表保留更高显示精度；示例值接近只能支持该点位的一致性，不能外推到全表真实性或“系统没有精度损失”。
\item flash 档效率差距明显：同样是产出结果，26 分钟 / 5{,}952 K 对 168 分钟 / 52{,}940 K，时长约为 1/6.5，token 约为 1/9。
\item 不完整的地方如实标注：约三分之一的探针在 GPL6244 注释里没有对应基因，系统原样保留这些行并明确标记，不悄悄丢弃，也不用猜测值填补；无法证实的数值刻度直接标为 unknown。
\end{itemize}

同时也有几个明确的缺陷：

\begin{itemize}
\item 纳入研究数少：本次 BioMed QAgent 观察单元为 1--2 个研究，Qoder 为 4--16 个；由于没有消融，原因未确定。
\item 需求中的差异表达在 BioMed QAgent 两个观察单元均未执行；这是本次交付缺口，而不是对系统分析能力的普遍判定。
\end{itemize}

综合起来，Gold1 的历史记录显示 BioMed QAgent 纳入研究较少且未执行差异表达，但提供了更强的结构化发布与字节审计；Qoder 覆盖更多研究并在 flash 单元执行了差异分析。由于逐条评审证据尚未按当前报告链冻结，本文不据此给出全表真实性优劣或普遍效率结论。

这些观察分成三条证据链：

\begin{itemize}
\item \textbf{时长与 token}：只对有冻结 usage 证据的单元报告观察值；由于没有重复且环境因素混杂，不作显著性或机制归因。
\item \textbf{交付覆盖}：gold1 沿用七条需求核对表；gold6 使用预注册的结构覆盖/可复用性 X 轴。两套量表不可直接合并或排序。
\item \textbf{证据可审计性}：BioMed QAgent 报告 Publication 回执、SHA-256、provenance 与 ProductAssessment；Qoder gold6 报告离线导出的 locator、manifest、QC 可复算程度和 raw/script 缺口。两者证明的是审计条件，不是未经逐值复核的科学真实性。
\end{itemize}
