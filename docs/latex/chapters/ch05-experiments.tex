\chapter{实验与评测}\label{ch:experiments}

本章从两个层面评测系统。首先在十个生物医学数据任务上报告端到端运行结果，考察正式发布、运行成本与阻断行为；随后选择表达组学任务 gold1 和文献活性数据任务 gold6，在两档模型和两种运行环境下比较效率、需求覆盖与证据可审计性。所有 BioMed QAgent 任务使用同一冻结系统版本。每个实验条件只运行一次，因此结果用于描述观察差异，不作统计显著性或单因素因果推断。

\section{实验设计总览与评测方法}\label{sec:eval-protocol}

BioMed QAgent 的输入为预先定义的研究任务描述。系统自动记录任务起止时间、模型用量、工具调用与终态，并对正式发布产物逐件校验文件大小和 SHA-256。运行时长取任务开始到终态的时间区间，token 为模型调用的总用量。终态分为成功发布、未发布阻塞、失败或取消。文件摘要校验用于确认交付文件完整且与发布记录一致，不单独代表科学结论正确或需求绝对查全。

对照环境使用相同的核心研究任务，并附带统一的 CSV 输出要求。Gold6 的对照结果根据导出的数据表、来源字段、清单和质量控制记录评估；由于其用量记录不完整，本章不报告该组的运行时长和 token，也不据此比较效率。

\section{对照设计与适用范围}\label{sec:factorial-design}

本节整理 gold1 与 gold6、flash 与 max、BioMed QAgent 与 Qoder 的八个观察单元。每个单元只有一次运行，没有重复、方差或显著性估计；跨环境提示词附加约束、默认推理参数和运行方式不同。因此，本节比较运行成本和产物差异，不作单因素因果推断。

\textbf{观察单元选择}。gold1 与 gold6 分别代表数据库型表达组学任务和文献/图表型活性证据任务；flash 与 max 代表两档模型。两个案例覆盖不同来源形态，但并非随机抽样，不能代表全部十类任务。模型参数由各环境分别配置，因此模型档位只用于组内比较。

\textbf{实验条件}。两种环境使用相同的核心研究任务和 CSV 交付目标。BioMed QAgent 将来源约束、质量检查与发布规则内置于系统；Qoder 通过用户消息给出相应要求。两种环境还采用各自默认的推理参数和运行方式，因此比较结果同时受到提示方式与执行机制影响。每个条件只运行一次，不估计随机波动或统计显著性。

对四个运行单元的产物有以下观察：

（1）交付形态。Qoder 每个研究输出一张宽表：一行是一个探针或基因，一列是一个样本，可以直接读入 R 或 Python。BioMed QAgent 发布的是长表：每个样本的每个探针或基因各占一行，并附带来源定位列，行数因此大两个数量级。两边的数据来自同样的 GEO 原始文件，区别在于表格为谁而做：宽表面向研究者直接使用，长表面向程序逐行核验。

（2）纳入研究数。Qoder flash 纳入 16 个研究，BioMed QAgent flash 发布 1 个、max 发布 2 个。该差异可能同时受来源选择、运行预算、Agent 决策、验证门禁和交付定义影响；当前没有消融实验，不能归因于某一机制。

（3）差异表达覆盖不同。题目要求通过两组样本比较得到差异表达；四组中只有 Qoder flash 交付了单研究差异分析和跨研究 meta 分析。BioMed QAgent 两档交付了带肿瘤/正常分组的表达表，但本次运行没有执行比较。该结果是运行级缺口，不应上升为系统永久不支持统计分析的边界。

（4）审计机制。Qoder 以来源 URL、文件 MD5 和检索日期支持人工抽查；BioMed QAgent 以来源定位、资产摘要和 Publication 回执支持机器核验。两者的证据形态不同，摘要匹配均不等价于值级真实性；当前只能说已记录的抽样未报告冲突。

核验结果也显示了 BioMed QAgent 的几个实际优势：

\begin{itemize}
\item 质量检查内建在发布之前。每次构建自动执行编码、数值类型、单位一致、行边界、溯源完整性等十项检查并留下报告；Qoder 侧的质量控制是人工填写的方法日志，两者约束力不同。
\item 在已抽查的示例中，Qoder flash 的基因矩阵显示为 3 位小数，BioMed QAgent 表保留更高显示精度；示例值接近只能支持该点位的一致性，不能外推到全表真实性或“系统没有精度损失”。
\item flash 档效率差距明显：同样是产出结果，26 分钟 / 5{,}952 K 对 168 分钟 / 52{,}940 K，时长约为 1/6.5，token 约为 1/9。
\item 不完整的地方如实标注：约三分之一的探针在 GPL6244 注释里没有对应基因，系统原样保留这些行并明确标记，不悄悄丢弃，也不用猜测值填补；无法证实的数值刻度直接标为 unknown。
\end{itemize}

同时也有几个明确的缺陷：

\begin{itemize}
\item 纳入研究数少：本次 BioMed QAgent 观察单元为 1--2 个研究，Qoder 为 4--16 个；由于没有消融，原因未确定。
\item 需求中的差异表达在 BioMed QAgent 两个观察单元均未执行；这是本次交付缺口，而不是对系统分析能力的普遍判定。
\end{itemize}

综合起来，Gold1 的结果显示 BioMed QAgent 纳入研究较少且未执行差异表达，但提供了结构化发布、来源绑定与文件校验；Qoder 覆盖更多研究，并在 flash 单元执行了差异分析。两种环境在覆盖范围和审计方式上各有侧重。

这些观察分成三条证据链：

\begin{itemize}
\item \textbf{时长与 token}：只对有冻结 usage 证据的单元报告观察值；由于没有重复且环境因素混杂，不作显著性或机制归因。
\item \textbf{交付覆盖}：gold1 按七项任务要求评分，gold6 按结构覆盖与复用性指标评分，最终统一映射为高、临界、低三级；原始分数只在同一案例内比较。
\item \textbf{证据可审计性}：BioMed QAgent 报告 Publication 回执、SHA-256、provenance 与 ProductAssessment；Qoder gold6 报告离线导出的 locator、manifest、QC 可复算程度和 raw/script 缺口。两者证明的是审计条件，不是未经逐值复核的科学真实性。
\end{itemize}
