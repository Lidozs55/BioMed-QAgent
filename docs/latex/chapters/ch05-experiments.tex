\section{实验设计总览与评测协议}\label{sec:eval-protocol}

为保证结果可复核，全部案例遵循同一评测协议：Agent 的输入只有案例需求原文（\code{TOPIC.txt}，数百字节的研究需求描述，不含任何参考答案或人工整理数据），BioMed QAgent 侧代码冻结在单一版本；由独立的外部监督程序驱动任务，把事件流持久化落盘，对发布产物逐件重新下载并重算字节与 SHA-256，最终给出三类终态判定（成功发布 / 未发布阻塞 / 失败或取消）。

评测模型统一为 qwen3.8 系列（\code{qwen3.8-flash} 与 \code{qwen3.8-max}，上下文窗口 1M），与赛题“基于国产开源大模型（Qwen/千问）”的设定对齐；图表理解链路（\ref{subsec:chart-vlm} 节）同样由 \code{qwen3.8-flash} 承担。

测量口径按环境如实分列：BioMed QAgent 侧的运行时长、token 用量（总量口径，不做入 / 出 / 缓存读拆分）与产物校验由监督程序自动采集；Qoder 侧由人工在会话内发起，并从平台会话记录导出时长与 token，指标操作化定义统一见 \ref{sec:comparison-metrics} 节。

\section{2×2×2 对照实验设计}\label{sec:factorial-design}

系统的机制贡献最终要回答一个问题：同一个模型、同一份需求，换一种运行环境，成本与质量如何变化。为此在两个代表性案例上构造 $2\times2\times2$ 全因子对照，共 8 个运行单元。

\textbf{因子选择}。案例因子取 gold1 与 gold6，代表两类能力面：gold1（乳腺癌 GEO 转录组整合）以多库查找、探针—基因映射、清洗与字段对齐为主，对应赛题核心能力 1--6；gold6（EGFR 突变体抑制实验论文图表提取）以正文与补充材料中的结合 / 抑制活性数值（IC50、Ki、Kd）与剂量—反应曲线提取为主，对应核心能力 7（图表数据处理）及加分项（图表识别 / 校验、低置信度人工修正）。两者参考集齐备、难度分层清晰，且分属“数据库型”与“文献型”两类来源形态。模型因子取 \code{qwen3.8-flash}与 \code{qwen3.8-max}，考察结论是否随模型档位稳健。环境因子取两种运行环境，定义如下。

\textbf{两种环境的输入构成}（关键事实，实验执行前冻结）：

\begin{itemize}
\item \textbf{BioMed QAgent}：用户输入只有 \code{TOPIC.txt} 原文（唯一合法任务输入）；赛题的各项要求不由用户消息携带，而是内化为系统提示词、治理工具与验证闸门。运行由监督程序驱动，事件流、token 用量与产物 SHA-256 自动落盘。
\item \textbf{Qoder}：用户输入 = \code{TOPIC.txt} 原文 + 赛题原文要求约束（附加条件与“应该完成的工作”原文），以单条用户消息给出；运行由人工在 Qoder 内发起；网络与 Python（pandas/numpy/scipy）可用。
\end{itemize}

gold1 在 Qoder 侧的完整输入原文如下（前半段为 \code{TOPIC.txt} 原文，其后为赛题原文要求约束；gold6 按同一构成规则生成，随实验执行一并冻结）：

\begin{keypoint}[gold1 · Qoder 侧输入原文]
主题：乳腺癌正常组织与肿瘤组织 GEO 转录组数据整合

查找公开的人类乳腺癌 GEO 转录组数据，研究对象为乳腺癌肿瘤组织与对应正常乳腺组织，希望能通过两组样本的基因表达比较得出差异表达。汇总所获研究的样本元数据、平台注释与表达数据（含探针与基因水平的对应），整理成便于后续分析的数据文件。

---

附加条件：仅将 CSV 文件作为正式产出

你应该完成的工作是：查找相关论文、开放数据库、表格、补充材料和图像数据，从正文、表格、附件或图表中提取可用信息，并整理输出合并后的多源 CSV 表格；完成数据清洗、字段对齐、来源标注和结构化输出；如涉及论文图像或图表，还应能够说明图表数据的识别、提取或校验方式。
\end{keypoint}

\textbf{控制变量与披露}。同一案例的 \code{TOPIC.txt} 原文跨环境逐字一致；BioMed QAgent 侧冻结同一产品 commit；每个单元仅做单次运行（不做重复采样，受算力与平台会话成本约束）；模型推理参数随各环境默认设置。需要如实披露的构成差异：BioMed QAgent 的用户消息只有 \code{TOPIC.txt}，而 Qoder 侧按其实际使用方式把赛题要求写入消息——该差异是“环境”因子的一部分：专用系统把约束内化为机制，通用环境只能以文本承载约束。

四个运行单元的比较呈现四点结构差异。其一，\textbf{交付形态分岔}：Qoder 侧以“每研究一张宽表矩阵”直出（每行一个探针 / 基因、每列一个 GSM 样本，可直接读入分析）；BioMed QAgent 侧以“单细胞溯源长表”发布（每样本 × 每探针 / 基因一行，行数大两个数量级，但每行携带资产标识与定位符），两者数据同源、形态面向不同消费者——前者面向人直接分析，后者面向管线复用与机器核验。其二，\textbf{广度差}：flash 档 Qoder 纳入 16 个研究，BioMed QAgent 同档仅 1 个（max 档 2 个）；统一协议下每个研究须走一次完整“采集—验证—发布”构建，广度让位于单研究深度的可验证交付。其三，\textbf{差异表达是共同的完整度缺口，但程度不同}：需求第 2 条要求“通过两组样本的基因表达比较得出差异表达”，四组中仅 Qoder flash 实际执行（单研究差异分析 + 跨研究 meta 分析两个交付文件），BioMed QAgent 两档均交付了可直接用于差异分析的肿瘤/正常分组表但未执行比较本身。其四，\textbf{真实性机制不同强度}：四组均未发现编造行，Qoder 以来源 URL、MD5 与检索日期支撑人工抽查，BioMed QAgent 则以逐格资产哈希链、验证闭环与发布产物逐件重验支撑机器核验——真实性结论一致，可复核方式与成本不同。

结果冻结后，观察沿四条线撰写（当前仅立框架，不预设结论）：

\begin{itemize}
\item \textbf{时长与 token}：环境机制（治理工具、验证闸门、进度上下文）对收敛轮次与往返成本的影响；flash 与 max 两档的成本—质量替换关系是否在不同环境下一致。
\item \textbf{完整度}：专用管线（表结构契约、溯源绑定）与通用环境的自由生成（CSV 直出）在需求条目覆盖面上的差异，以及该差异在 gold1（数据库型）与 gold6（文献图表型）两类任务上的不同表现。
\item \textbf{真实性}：来源标注与复核通道的有无如何改变编造风险与可核查性；结构化阻断与“自由发挥补齐”在同一需求上的分岔。
\end{itemize}
