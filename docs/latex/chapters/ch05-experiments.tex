\section{案例 gold7：阿尔茨海默 GWAS 风险位点整合（动态 Family 全链闭环）}

\textbf{输入（TOPIC 摘要）}：以 Bellenguez 2022（PMID 35379992）等来源整合 AD GWAS 风险位点，输出研究、位点、变异-基因映射三张表，要求补充材料 75 位点表解析与 GRCh38 坐标核验。
\textbf{过程要点}：Agent 首步调用路线检查（\code{inspect\_\allowbreak{}dataset\_\allowbreak{}execution\_\allowbreak{}routes}），确认静态注册表无任何数据家族能表达该三表拓扑后选择动态路线；随后经治理工具完成采集——GWAS Catalog REST 返回 GCST90027158 的 89 条全基因组显著关联；Europe PMC 官方补充通道取得 27,656,649 字节归档（SHA-256 逐字节登记后作为任务资产），Core 提取器将 XLSX 成员逐工作表转为溯源绑定的 UTF-8 CSV 资产；dbSNP 工具核验 GRCh38 坐标。正式发布前，动态预检拒绝了 11 次规格提交（角色映射、输入闭包、外键策略、字段形状等），每次均给出可操作的错误信息；Agent 修正后发布 v1，又自行发现 v1 的 GWAS 统计列未填充与解析缺陷，发布修正版 v2 并以替代关系保留 v1 历史——这一"自检-修正-换版"行为正是 4.9 节反馈修正闭环的实测样本。
\textbf{输出结构（v2，\code{study.csv} 1 行、\code{locus.csv} 88 行、\code{variant\_\allowbreak{}gene\_\allowbreak{}mapping.csv} 127 行）}：\code{locus.csv} 24 列，含双坐标基准对照（\code{position\_\allowbreak{}grch38} 与补充材料 \code{position\_\allowbreak{}grch38\_\allowbreak{}supp}）、分层统计（\code{stage1/\allowbreak{}stage2/\allowbreak{}stage12} 的 OR 与 p 值）、异质性（\code{i2}/\allowbreak{}\code{phet}）与来源标记（\code{in\_\allowbreak{}supp\_\allowbreak{}75\_\allowbreak{}loci}、\code{dbsnp\_\allowbreak{}variant\_\allowbreak{}type}）。真实样例行：

\section{案例 gold8：DILI 风险药物证据整合（来源失效下的正确终态）}

\textbf{输入（TOPIC 摘要）}：针对 DILIrank 2.0 vMost 药物整合三类证据——DILIrank 标签注释、LiverTox 专论、openFDA FAERS 肝毒性 PT 报告计数，约 50 种代表药、四表交付。
\textbf{关键难点与行为}：DILIrank 2.0 官方文件（\code{fda.gov/\allowbreak{}media/\allowbreak{}113052/\allowbreak{}download}）持续 404，LiverTox 无药物级结构化导出。系统的处理展示了赛题"自动识别缺失数据……完成修正或寻求人类建议"加分项的完整链路：第一轮运行在发现阶段确认官方来源不可达后\textbf{未编造任何行}，以工作区暂存 +\allowbreak{} 结构化阻断收尾，明确请求"提供官方文件或注册 Core 资产"；第二轮定向续跑把可达维度（FAERS 计数）正式化——9 个已验证药物各经一条 \code{openfda.files.v1} Core 采集绑定\textbf{重新获取}（发现阶段的查询输出不被当作正式载体），以动态数据家族发布。
这一"核实不可达 → 显式阻断 → 定向续跑 → 正式化可达维度"的降级链，把提案加分项"自动识别缺失数据并完成修正或寻求人类建议"落在数据链路的每个环节；不可达维度的替代源自动发现（从文献补充或其他官方通道补 DILI 证据，并把尝试过程计入覆盖证据）已列入改进项。
\textbf{输出结构}：\code{faers\_\allowbreak{}reaction\_\allowbreak{}counts.csv} 68 行 × 5 列（\code{drug\_\allowbreak{}name, reaction\_\allowbreak{}pt, report\_\allowbreak{}count, retrieval\_\allowbreak{}method, source\_\allowbreak{}url}）。请求的 9 药 × 8 肝毒性 PT = 72 行中，4 行因官方聚合响应确无该 PT 词条而\textbf{未零填充}，逐条列出（如 azathioprine–HEPATOCELLULAR INJURY）；其余 68 行与发现阶段 openFDA 计数逐条一致（如 acetaminophen ACUTE HEPATIC FAILURE = 3297）。校验 16/\allowbreak{}16 通过（0 坏行、0 重复主键）、溯源 9/\allowbreak{}9 载体满足、\code{product\_\allowbreak{}status=publishable}。每行 \code{source\_\allowbreak{}url} 直接给出可复核的官方 API 查询串；\code{report\_\allowbreak{}count} 的语义为 MedDRA PT 报告次数（非去重患者、非因果证据），已在终答与溯源中注明。
不可达的 DILIrank vMost 名册与 LiverTox 维度不进入正式发布，仅保留为明确标注暂存的工作区文件——"部分维度正式发布 +\allowbreak{} 不可达维度结构化阻断"是该上游条件下唯一诚实的完成形态，也是 4.7 节显式终态语义的一次实战兑现。其余边界见 5.8。

\section{结构化输出样例与字段说明}

以 gold9 跨源证据交叉表为例（真实发布行）：
\begin{lstlisting}[style=papercode]
hgnc_symbol,orphacode,clingen_classification,clingen_classification_date,clingen_disease_label,clinvar_count,clinvar_query,conflict_flag,conflict_detail
TBX1,567,,,,,,NONE,
\end{lstlisting}

字段语义：\code{clingen\_\allowbreak{}classification} 为 ClinGen 基因-疾病有效性分类（如 Definite/\allowbreak{}Strong/\allowbreak{}Limited；Refuted/\allowbreak{}Disputed 出现时触发冲突逻辑）；\code{clinvar\_\allowbreak{}count} 为 ClinVar 该基因致病记录计数，\code{clinvar\_\allowbreak{}query} 保留实际查询串以供复核；\code{conflict\_\allowbreak{}flag} 取 \code{NONE} 或 \code{CONFLICT\_\allowbreak{}CLINGEN\_\allowbreak{}REFUTED\_\allowbreak{}OR\_\allowbreak{}DISPUTED\_\allowbreak{}WITH\_\allowbreak{}ORPHANET\_\allowbreak{}ASSOCIATION}，\code{conflict\_\allowbreak{}detail} 列出冲突的 ClinGen 疾病标签。空值即"来源未覆盖该单元格"，系统不以零或推断填充（gold9 中 ClinVar/\allowbreak{}ClinGen 两列整体为空的边界说明见 5.8）。
来源凭据样例（\code{provenance.json} 中 \code{input\_\allowbreak{}asset\_\allowbreak{}receipts} 的第一条，逐字段）：
\begin{lstlisting}[style=papercode]
{ "asset_id": "asset_df8d562a0c6011af…c0962bbb", "role": "in_0",
  "sha256": "df8d562a0c6011af36a74eb4000ce81ca7d723e8031010819fb71727c0962bbb",
  "size_bytes": 54026799, "locator_ref": "asset_df8d562a0c60…c0962bbb" }
\end{lstlisting}

即：输入不是"一个下载文件"，而是（任务、来源、字节摘要、采集实现身份）共同绑定的证据对象。发布清单（\code{dataset\_\allowbreak{}manifest.json}）对每个文件登记相对路径、媒体类型、字节数与 SHA-256（如 gold8 主表 13,558 B /\allowbreak{} \code{08e9db4f…}，清单文件摘要 \code{1ec9f4ab…}）；读取端每次读取都重算摘要，文件被改动即拒绝展示。
