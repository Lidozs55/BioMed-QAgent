## 已修改的论述

### 成本与效率

第五、六章不再将样例6较低的时长和 token 总量称作同等任务下的效率优势。保留原记录数值与图表，说明两环境的交付范围和计量方式不同。删除“对照方交付更多，所以差距与工作量无关”及“相同模型名称即可认定单价一致”等推论。

### 发布与需求完成

第一、二、三、五、六章统一区分正式发布状态与原始需求完成情况。11/12＝91.7%仍保留为跨批次列示运行的正式发布比例，不称需求完成率。补充已归档六运行批次5/6＝83.3%的范围说明，两种分母不互换。样例8注明仅FAERS相关内容正式发布；样例9说明动态产品与原静态四表规格不同。

### 实验范围与尚未完成的评分

补充六运行批次的代码版本、提示来源和 max 配置差异，不再笼统称全部运行只输入统一TOPIC原文。Qoder时长与用量仍标为人工记录，不换算费用。

上传稿的样例6四组统一评分仍写着“待重跑数据”，但总表已经给出“高”“边界”。本次删除这些缺少完整依据的总分档位，不套用旧版源码中的另一组分数。原有Qoder两份离线包的X/Y分项与均值保留，只在该案例内部说明，不作为四组需求覆盖分或数值正确率。样例1已有任务条目评分保留；没有完整记录的可审计性总分不补填。

### 文件重验与跨次复现

将“文件摘要一致”限定为文件与回执相符，不以其证明重跑结果相同或科学数值正确。明确重复执行还需固定来源、代码、参数与模型抽取结果，本次没有新增重跑实验。

### 人工审批与候选执行

删除“人工响应晚于请求就拒绝”等不准确措辞，改为检查请求是否有效、对象是否仍匹配证据。区分已经发起的强制人工请求与发布路径是否实际触发请求；保留样例7、9无业务HIL的记录，不据此宣称所有动态路径均执行人工验收。HIL请求次数也不直接视为人工实际操作次数。

候选与正式文件的分开管理不再写成操作系统级沙箱保证。主架构图和Core详图同步将“不能产生数据值”改为“可生成候选，不直接发布”，避免图文相互矛盾。

### 图表、数值与相关工作

将轴和图例规则表述为声明与点数据的一致性检查，不声称自动识别所有误读。样例1的4.1862与4.186仅说明输出小数位不同，不凭两个系统互查推定哪一方更接近原始值。

相关工作改为比较各工具提供的能力及本系统的具体组合，不再断言通用框架无法绑定审批证据或进行校验。参考文献按所引版本核对：DocETL使用 arXiv:2410.12189v1 的题名和作者；Palimpzest使用 Liu等人的《A Declarative System for Optimizing AI Workloads》。引用列表和交叉引用同步修正。

### 中文与排版

压缩重复解释，保留数据处理流程与实例，使引言、方法、实验和结论采用一致说法。短表保持完整，长案例表保留跨页表头，避免小表只剩一行跨页；调整目录与图文排列，避免大型图旁过窄的正文栏。成品由30页缩至25页，没有通过缩小正文字号压页。
