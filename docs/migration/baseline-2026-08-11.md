## Executable DatasetBuild golden baseline

`tests/migration/golden/` freezes four current V2 business outcomes using the
real Pydantic contracts and repository-local source data:

- `succeeded`: a local GDC source is built, validated, and published by the
  deterministic `ExpressionBuildRunner` + `DatasetBuildExecutor` path.
- `partial_success`: an empty local GDC source is rejected while the local
  Xena source is built, validated, and published.
- `no_data`: a header-only local source produces a structured
  `no_primary_data` outcome and explicitly has no ValidationResult, manifest,
  publication, or artifact.
- `spec_rejected`: the pure current `SpecValidator` returns `unknown_schema`;
  the contract-valid BuildResult explicitly has no validation, manifest,
  publication, or artifact. The legacy tool currently exposes the validator
  result directly; wiring this BuildResult into the future service boundary is
  intentionally outside Phase 0D.

Published fixtures contain the exact manifest artifact files. Every source and
artifact reference records its repository path, role or binding, size, and
SHA-256. Each outcome also contains a current-contract `EventEnvelope` sample.
The contract snapshot is generated from `model_json_schema()` for
DatasetBuildSpec, BuildResult, ValidationResult, DatasetManifest,
DatasetPublication, and EventEnvelope.

The verifier canonicalizes only timestamps, EventEnvelope event IDs, and
natural-language summary/message fields. Status, reason codes, source coverage,
manifest roles, validation status, publication relationships, and artifact
hashes remain strict comparison fields.

## Reproduction commands

Reproduce the historical legacy checks in a separate worktree at the frozen
base commit:

```powershell
git worktree add ..\BioMed-QAgent-baseline-2026-08-11 8fe0773fd498ac688dd2df72b30f2ff2fddaf868
Set-Location ..\BioMed-QAgent-baseline-2026-08-11\backend
uv sync --frozen
uv run ruff check app/ tests/ launcher.py
uv run pytest
Set-Location ..\frontend
corepack pnpm install --frozen-lockfile
corepack pnpm test
corepack pnpm lint
corepack pnpm tsc
corepack pnpm build
```

Verify the committed golden baseline from the current repository:

```powershell
Set-Location backend
uv run python ..\scripts\verify_migration_golden.py
uv run pytest tests/test_migration_golden.py -q
```

Normal verification is read-only. Regeneration is an explicit review action:

```powershell
Set-Location backend
uv run python ..\scripts\verify_migration_golden.py --capture
git diff -- tests/migration/golden tests/migration/sources
```

No golden command performs live network access.

## Known limitations

- The full backend baseline did not finish within 15 minutes; its final result
  is unknown.
- Live tests and real upstream downloads are excluded. Golden sources are
  small, committed local fixtures and do not prove current provider uptime.
- React `act(...)` stderr and the Vite chunk-size warning are pre-existing and
  intentionally recorded rather than suppressed.
- The baseline freezes current DatasetBuild contract and deterministic-builder
  semantics only. It does not install Pi, change runtime behavior, or validate
  the future TypeScript bridge.
