# 临床与试验数据

覆盖临床队列、EHR/登记、随机/非随机试验数据的查找、获取与可分析性判断。BioMedQAgent
交付的是**结构化可分析数据**（临床表/试验数据集的整理），统计推断由下游承担。

## 1. 数据层级与"一行代表什么"

- 先建立受试者、就诊、医嘱、给药、检验、诊断、结局、标本和中心之间的关系；
- **不要把事件表行数当作患者数**：明确一行是患者、就诊还是事件，分别给出记录数、
  唯一患者数、完全重复、主键重复和冲突组；
- 主键与连接基数显式检查；多对多连接先说明预期膨胀。

## 2. 时间与分组语义

- 区分记录时间、采集时间、发生时间、入库时间与修订时间；
- 以时间零点为中心检查结局、暴露和随访顺序；日期倒置先称"时间逻辑不一致"，不自动
  推断偏倚类型或删失规则；
- tumor/normal、处理/对照等分组字段若分散在 `treatment` 等自由文本中，整理时结构化
  出明确的 `sample_group`/`pair_id` 列供下游差异分析直接使用；
- 字段名只能支持候选解释：没有方案/字典/用户说明时，不自动定义 `index_date`、暴露
  策略或纳排规则，保留为待确认项，先完成不依赖这些定义的盘点。

## 3. 编码与映射纪律

- 对 ICD、药品、检验或不良事件编码，先记录 `coding_system`、版本、地区/扩展与来源字典；
- 仅大小写/首尾空格等可证明安全的差异可作确定性统一；跨版本/跨体系映射必须有版本化
  字典或用户映射表支持；
- 来源或版本未知时**保留原编码**，可另给 `candidate_code_normalized` +
  `mapping_status=unverified` 候选，但不得把候选值当已验证编码用于主数据纳入或分组。

## 4. 缺失与样本流

- 区分结构性不适用、未测、失访、无效编码、意外缺失和未知；结构性不适用单独报告，
  不计入"存在质量问题"记录数；
- **"未记录"不等于"未发生"**；暴露缺失不等于未暴露；`Unknown` 只能作缺失标记；
- 样本流至少覆盖：筛选、纳入、分组、随访、结局可评估及各分析集人数；
- 主键冲突无源系统优先级时**保留冲突组**或给整组排除的条件性计数，不默认取首行/末行。

## 5. 试验数据要点

- 对齐随机分组、实际治疗、停药、脱落、结局可评估与各分析集人数；
- 分析集定义（ITT/PP/安全集）及其一致性记录清楚；"完整病例"只能称可评估病例分析；
- 方案偏离、救援治疗、交叉、失访与 intercurrent event 需要保留标记字段；
- 数据库未锁定或版本持续变化时，注明版本状态与局限。

## 6. 与表达/组学数据整合的边界

- 临床数据与表达数据**按 accession/source_id 交叉引用**，不做跨 family 行级合并
  （一个 Build 一种 family/granularity）；
- 同一患者跨表/去标识后的链接不确定性需量化或标记，不要把无法个体级连接的表拼接。
