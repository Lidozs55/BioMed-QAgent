# Reviewer C — Phase 4 Frontend Bug Sweep

Base: `main@08c961c` / branch `fix/phase4-review-bugs`  
Scope: runtime transport/controller/reducers/store, RunSummary UI, artifacts/results, empty-table semantics, and `data_correction` HIL. No production files were modified.

## Findings

| ID | Severity | File:line | Bug and concrete failure scenario | One-line fix | Vitest-style repro sketch |
|---|---|---|---|---|---|
| C1 | Critical | `frontend/src/runtime/transport.ts:16-57`, `:686-693` | `publication_created` is absent from `EVENT_TYPES`, so every live/replayed WebSocket publication event is rejected before the reducer. If artifact events are sequence 10, `publication_created` is 11, and `run_completed` is 12, the client applies 12 and permanently advances past 11; `currentPublicationId`/`publications` stay stale until a later REST snapshot happens to hydrate them. | Add `publication_created` to the accepted transport event set and cover the real transport-to-reducer path. | Connect `AgentEventTransport`, subscribe, send a valid `publication_created` envelope, then expect `tasksById[id].currentPublicationId === "pub-1"` and `lastSequence` advanced. Current code leaves both unchanged. |
| C2 | Important | `frontend/src/runtime/reducers/index.ts:41-48`, `:150-157`; `frontend/src/runtime/transport.ts:686-693` | Event application accepts any `sequence > lastSequence`; it never detects a gap. Any rejected/unknown/schema-drift frame at N followed by a valid N+1 frame advances the cursor to N+1, so reconnect subscribes after N+1 and the missing event is unrecoverable. A dropped `user_input_required` followed by an assistant/warning event can leave a paused backend run with no dialog forever. C1 is a current concrete trigger of this generic flaw. | Require contiguous sequences, buffer/recover on `sequence > lastSequence + 1`, and only advance after the gap is replayed. | Seed `lastSequence=4`; deliver sequence 6 and assert it is not reduced and recovery is requested from 4; then deliver 5 and 6 and assert both effects and final cursor 6. Current reducer applies 6 immediately. |
| C3 | Important | `frontend/src/runtime/controller.ts:94-120`, `frontend/src/runtime/transport.ts:419-432`, `:646-657` | Terminal tasks are reclassified in the store but never unsubscribed from the transport. Every task that completes/fails/cancels remains in `desired` and is resubscribed on every reconnect, retaining client/server subscriptions for the lifetime of the page. A long session accumulates one permanent WebSocket subscription per completed task. | Reconcile desired subscriptions with `activeItems` after terminal events (or have the event integration unsubscribe a task once its authoritative run terminalizes). | Start with one subscribed running task, deliver `run_completed`, reconnect, and expect no subscribe command for that task. Current reconnect emits it again. |
| C4 | Important | `frontend/src/runtime/reducers/runtime.ts:287-331`; `frontend/src/components/UserInputDialog.tsx:149`, `:212-221` | `run_cancel_requested` does not clear the run's `pendingUserInput`, and dialog openness depends only on that stale prompt. Cancelling an `AWAITING_USER_INPUT` run therefore leaves the blocking correction/confirmation modal active throughout cancellation; its buttons can still call resume and race the cancellation, producing a stale-request error or transiently restarting the UI state. | Clear the owning prompt on `run_cancel_requested` (and any transition that proves the run is no longer awaiting input), and disable dialog actions outside `awaiting_user_input`. | Reduce `user_input_required` then `run_cancel_requested`; render `UserInputDialog`; expect no dialog and no resume action. Current code keeps it open and enabled. |
| C5 | Important | `frontend/src/runtime/reducers/hil.ts:51-74` | Every `user_input_resumed` forces its envelope run and the task summary to `running` before checking whether request/run matches the pending prompt. A late/mismatched resume after `cancel_requested`, or an old resume after a newer prompt, can regress the task to RUNNING while leaving the real prompt pending. Existing reducer coverage checks that another run's resume preserves the prompt but misses that it corrupts `summary.status` and `active_run_id`. | Treat resume as a state-machine transition only when the current pending `{runId, requestId}` matches; otherwise ignore it except for cursor advancement/diagnostics. | Reduce prompt for `run-a/request-new`, then `user_input_resumed` for `run-a/request-old` (or `run-b`); expect status/prompt/active run unchanged. Current code sets RUNNING and may switches active run. |
| C6 | Important | `frontend/src/components/ChatPanel.tsx:247-254`, `:447-460` | The four-state UI renders only a short label. Structured `RunSummary` details are otherwise discarded: `BuildResult.user_summary` and `recommended_next_action` are not shown for SUCCEEDED/PARTIAL_SUCCESS/SPEC_REJECTED, failed `error_code`/`user_message` are hidden, and `cancelled_at_stage` is never rendered anywhere in components despite the Phase 4a acceptance claim. Concrete result: `SPEC_REJECTED` says only “规格被拒” with no correction action; cancellation at validation says only “任务已取消”. | Render a compact latest-run summary driven by `run.summary` for all terminal paths, including recommended action, stable error category, and cancellation stage. | Render `ChatPanel` with terminal runs for `partial_success`, `spec_rejected`, failed, and cancelled-at-processing; assert server summary/action/error/stage text is visible. Current tests assert labels only. |
| C7 | Important | `frontend/src/components/ResultsViewer.tsx:300-343` | NO_DATA artifact ownership is inferred from `available_artifact_roles.length > 0 && artifacts.length > 0`. Roles are only type names, not run/publication ownership. With task-wide artifacts retained from run A and a latest NO_DATA run B that declares a supporting/audit role, B's banner and empty-preview message are attached to A's files, misrepresenting old data as the latest result. The Phase 4b review already notes the missing ownership metadata. | Carry `run_id`/`publication_id` on artifact projections and filter/banner against the latest run's actual artifacts; do not infer ownership from role presence. | Seed an old primary/supporting artifact from run A and latest run B as NO_DATA with `available_artifact_roles:["supporting_dataset"]`; expect no B summary over A's artifact. Current `showNoDataBanner` is true. |
| C8 | Minor | `frontend/src/components/UserInputDialog.tsx:380-387` | `expires_at` is presentation-only: a deadline already in the past still renders “需在 … 前答复” and leaves both actions enabled. During reconnect/replay delay, the user can type into an already-expired correction and only discover staleness after a rejected API call; the dialog can remain blocking until the synthetic resume arrives. Invalid timestamps also render `Invalid Date`. | Parse/validate the deadline, show an expired state, disable submission at/after expiry, and let the durable resume event close the dialog. | Use fake timers with `expiresAt` one second in the past; expect “已超时” and disabled actions. Current buttons remain enabled and text claims the past deadline is actionable. |
| C9 | Minor | `frontend/src/components/ResultsViewer.tsx:57-75`, `:177-210` | A header-only CSV is treated as a populated table because emptiness checks only `headers.length`. Legitimate empty supporting/audit tables render a bordered header with a blank body rather than the NO_DATA/“无数据” state, contradicting Phase 4b empty-table semantics. | Treat `rows.length === 0` as an empty dataset (optionally retain a schema/header note) and render the explicit empty state. | Mock artifact text as `"sample_id,condition\n"`, open preview, and expect the empty-state title rather than a table. Current code renders a table with zero rows. |
| C10 | Minor | `frontend/src/components/ArtifactSheet.tsx:93-95` | The main `ResultsViewer` classifies files with `fileType(name, role)`, but `ArtifactSheet` drops `artifact.role`.
